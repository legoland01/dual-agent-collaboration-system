## 1. 背景

### 1.1 问题

oc-collab 项目需求来源多元化：

| 来源 | 说明 | 问题 |
|------|------|------|
| Agent 提交的 Proposal | Agent 主动提出 | 分散在 Git 中 |
| Bug 记录 | Bug 修复需求 | 缺乏统一追踪 |
| 内部 Memo/会议纪要 | 讨论产生的需求 | 散落在各版本 |
| OpenCode 用户对话 | 用户直接输入 | 无收集机制 |
| 外部客户需求 | 客户/用户提出的需求 | 无处理流程 |

**核心问题**：没有统一的需求收集入口，需求分散、丢失、遗忘。

### 1.2 核心洞察

```
需求来源多元化 → 需要统一收集管道
↓
多人协作 → 需要 Git 同步机制
↓
周期性梳理 → 需要明确节奏和责任人
```

---

## 2. 目标

### 2.1 核心目标

| 目标 | 实现方式 |
|------|----------|
| 统一入口 | 所有需求进入同一目录 |
| 零门槛收集 | 不做评审，直接收集 |
| 定期梳理 | 每版本开发完成后 Agent 1 梳理 |
| 状态透明 | 每个需求有明确状态 |

### 2.2 预期收益

| 收益 | 说明 |
|------|------|
| 需求不丢失 | 所有需求进入统一管道 |
| 追溯能力强 | 记录来源、时间、状态变化 |
| 节奏可控 | 每版本梳理一次，不混乱 |

---

## 3. 解决方案

### 3.1 需求收集目录

**目录**：`docs/04-incoming/`

**结构**：
```
docs/04-incoming/
├── README.md                 # 本流程说明
├── STATUS.yaml              # 需求状态追踪
├── incoming_YYYYMMDD_001/   # 需求输入目录
│   ├── PROPOSAL_xxx.md      # Agent 提交的 Proposal
│   ├── BUG_xxx.md           # Bug 记录
│   ├── MEMO_xxx.md          # 内部 Memo
│   ├── USER_INPUT_xxx.md    # 用户对话导入
│   └── EXTERNAL_xxx.md      # 外部需求（暂缓）
```

**规则**：
- 任何人可提交需求到 `docs/04-incoming/`
- 不做评审，直接收集
- 保留原始输入格式
- 记录提交人、时间戳、来源

### 3.2 状态流转

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| PENDING | 待梳理 | 需求提交后自动设置 |
| IN_REVIEW | 梳理中 | Agent 1 开始梳理 |
| ACCEPTED | 已采纳 | Agent 1 评估后采纳 |
| REJECTED | 已拒绝 | Agent 1 评估后拒绝 |
| DEFERRED | 已推迟 | Agent 1 评估后推迟 |

**流转图**：
```
PENDING (提交后)
    ↓ Agent 1 梳理
IN_REVIEW (梳理中)
    ↓ Agent 1 评估
├─ ACCEPTED (采纳) → 进入开发流程
├─ REJECTED (拒绝) → 记录原因
└─ DEFERRED (推迟) → 后续版本
```

### 3.3 定期梳理机制

**频率**：每版本开发完成后

**触发条件**：
- 一个版本开发完成，发布后
- Agent 1 自动检查 `docs/04-incoming/`

**梳理流程**：
1. 检查新需求（状态 PENDING）
2. 评估是否纳入下一版本
3. 更新状态（ACCEPTED/REJECTED/DEFERRED）
4. ACCEPTED 的需求进入 `requirements_vX.X.X_DRAFT.md`

**梳理输出**：
- 更新 `STATUS.yaml`
- 创建 `docs/04-incoming/REVIEW_YYYYMMDD.md` 梳理报告

### 3.4 来源标记

| 来源类型 | 前缀 | 示例 |
|----------|------|------|
| Agent Proposal | PROPOSAL_ | PROPOSAL_v2.2.3_Git_Commit.md |
| Bug 记录 | BUG_ | BUG_20260208_001.md |
| 内部 Memo | MEMO_ | MEMO_20260208_001.md |
| 用户输入 | USER_INPUT_ | USER_INPUT_20260208_001.md |
| 外部需求 | EXTERNAL_ | EXTERNAL_20260208_001.md |

## 4. 多人协作机制

### 4.1 Git 同步

| 场景 | 工作流 |
|------|--------|
| 提交需求 | git add + commit + push → Gitee/GitHub |
| 评审需求 | Pull Request / Merge Request |
| 同步状态 | pull → 修改 → push |

### 4.2 冲突解决

| 冲突类型 | 解决方式 |
|---------|----------|
| 同一需求重复提交 | 合并，标记重复 |
| 状态冲突 | 后提交者解决，或讨论解决 |
| 内容冲突 | PR 中讨论解决 |
