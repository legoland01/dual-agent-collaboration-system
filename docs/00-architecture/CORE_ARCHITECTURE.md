## 1. 架构概述

### 1.1 文档定位

本文档定义 oc-collab 双Agent协作框架的**核心功能架构**，是所有功能开发的长期参考基准。

| 属性 | 值 |
|------|-----|
| **稳定性** | 长期稳定，不随版本迭代 |
| **适用范围** | 所有功能开发、需求分析、设计评审 |
| **维护原则** | 架构变更需经Agent1+Agent2评审通过 |

### 1.2 架构设计原则

| 原则 | 说明 |
|------|------|
| **职责清晰** | 每个功能模块有明确的职责边界 |
| **层次分明** | L1核心流程 → L2保障机制 → L3基础设施 → L4增强能力 |
| **可追溯** | 每个功能点可追溯到架构模块 |
| **可扩展** | 预留扩展空间，不过度设计 |

### 2.2 架构层级说明

| 层级 | 功能模块 | 说明 | 优先级 |
|------|----------|------|--------|
| **L1** | 核心协作流程 | 需求 → 设计 → 开发 → 测试 → 部署 | 最高 |
| **L2** | 协作保障机制 | 角色边界、签署流程、阶段推进 | 高 |
| **L3** | 基础设施 | 状态管理、Git集成、Skill系统 | 中 |
| **L4** | 增强能力 | 双机协作、文档版本管理 | 低 |

### 2.3 模块详细说明

#### 1. 需求管理

| 子模块 | 职责 | 核心产出 |
|--------|------|----------|
| 1.1 需求分析 | 版本结束后需求收集与分析 | 需求分析报告 |
| 1.2 需求文档管理 | 需求文档创建、版本控制 | requirements_vX.X.X.md |
| 1.3 需求评审 | 7视角评审 + 逆向验证 | 评审意见 + 签署 |
| 1.4 需求追溯 | 需求 → 设计 → 代码 → 测试 | 追溯链 |

**架构映射规则**：
- 新增需求相关功能 → 标注 `1.x`
- 需求分析报告模板 → 映射到 `1.1`
- 需求评审规范 → 映射到 `1.3`

#### 2. 设计管理

| 子模块 | 职责 | 核心产出 |
|--------|------|----------|
| 2.1 概要设计 | 功能模块抽象、用户视角 | OUTLINE_vX.X.X.md |
| 2.2 详细设计 | 技术实现细节、接口定义 | DETAIL_vX.X.X.md |

**架构映射规则**：
- 设计文档模板 → 映射到 `2.1` 或 `2.2`
- 设计评审规范 → 映射到对应设计阶段

#### 3. 开发管理

| 子模块 | 职责 | 核心产出 |

| 3.1 代码实现 | 模块开发、代码规范 | src/**/*.py |

**架构映射规则**：

## 3. 功能映射规范

### 3.1 映射模板

每个新功能必须标注架构映射：

```markdown
## 功能映射

| 属性 | 值 |
|------|-----|
| **架构模块** | X.y 子模块名称 |
| **映射路径** | 核心架构 → X.y |
| **依赖模块** | 无 / 其他模块 |
| **影响范围** | 本模块 / 跨模块 |
```

### 3.2 映射示例

**示例1：todowrite自动检查**

| 属性 | 值 |
|------|-----|
| **架构模块** | 7.2 任务状态 |
| **映射路径** | 核心架构 → 7.2 |
| **依赖模块** | 无 |
| **影响范围** | 本模块 |

**示例2：Skill切片检索**

| 属性 | 值 |
|------|-----|
| **架构模块** | 9.2 Skill管理 |
| **映射路径** | 核心架构 → 9.2 |
| **依赖模块** | 7.1 项目状态 |
| **影响范围** | 跨模块 |

### 3.3 映射检查清单

需求评审时检查：

- [ ] 每个功能点有明确的架构映射
- [ ] 映射路径与架构层级一致
- [ ] 依赖关系清晰
- [ ] 影响范围可控
