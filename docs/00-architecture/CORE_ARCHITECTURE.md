## 1. 架构概述

### 1.1 文档定位

本文档定义 oc-collab 系统的**核心功能架构**，包含L1到L3的完整设计。

| 属性 | 值 |
|------|-----|
| **稳定性** | L1核心稳定，L3快速迭代 |
| **适用范围** | 所有功能开发、需求分析、设计评审 |
| **维护原则** | 架构变更需评审通过 |

### 1.2 架构分层

```
┌─────────────────────────────────────────────────┐
│  L3: PM-Agent (单点入口)                       │
│  (项目汇总、需求分发、进度查看)                 │
├─────────────────────────────────────────────────┤
│  L2: TODO系统 (全局共享)                        │
│  (Agent注册、跨项目路由、积压队列)              │
├─────────────────────────────────────────────────┤
│  L1: oc-collab-core (项目内流程)               │
│  (Agent1+2工作流、签署、Skill、Git/部署)      │
└─────────────────────────────────────────────────┘
```

**说明**：
- L1 (oc-collab-core): 每个项目独立运行，只管项目内流程
- L2 (TODO系统): 全局共享，支持跨项目任务传递
- L3 (PM-Agent): 单点入口，方便用户使用

**详细说明**: 见 `RESEARCH_Multi_Project_Collaboration.md`

### 2.2 Skill系统设计

| 能力 | 说明 |
|------|------|
| **模板机制** | 新项目自动加载标准模板，支持继承定制 |
| **锁定控制** | 项目owner可锁定强制使用标准版 |
| **自动升级** | 检测并同步主项目Skill变更 |

### 2.3 刚性框架设计

#### 2.3.1 分层架构

```
┌─────────────────────────────────────────────────┐
│  L2: 审计层 (事后)                              │
│  - 行为分析、异常检测、审计日志                  │
├─────────────────────────────────────────────────┤
│  L1: 强制层 (不可跳过)                          │
│  - 里程碑锁、审批权校验、自验收阻断              │
├─────────────────────────────────────────────────┤
│  L0: Skill层 (可配置)                          │
│  - 覆盖率阈值、验收标准                          │
└─────────────────────────────────────────────────┘
```

#### 2.3.2 响应梯度

| 响应 | 代码 | 说明 |
|------|------|------|
| 阻止 | R1 | 直接阻断，返回错误 |
| 警告+记录 | R2 | 允许通过，记录日志，定期审计 |
| 允许+审计 | R3 | 完全通过，标记待审，人工复核 |

#### 2.3.3 触发机制

| 类型 | 说明 | 示例 |
|------|------|------|
| 前置检查 | 操作前拦截 | 里程碑完成前检查前置 |
| 后置验证 | 操作后验证 | 提交后检查测试覆盖率 |
| 周期扫描 | 定时检查 | 每日扫描未关闭TODO |
| 随机抽查 | 概率触发 | 20%交付物二次验证 |

#### 2.3.4 核心规则

| 规则ID | 风险类型 | 响应 | 说明 |
|--------|----------|------|------|
| RF-001 | 自验收 | R1 | 禁止自己验收自己的代码 |
| RF-002 | 里程碑跳过 | R1 | 前置未完成则阻断 |
| RF-003 | 共谋 | R1/R2 | 审批权限校验+随机抽查 |
| RF-004 | 数据伪造 | R2 | 内容指纹+外部验证 |

#### 2.3.5 与Skill的关系

- Skill层(L0)在刚性层之下，可配置部分不得低于刚性底线
- 刚性层(L1)规则不可跳过，优先级 > Skill
- 审计层(L2)记录所有行为，供PM-Agent查看

#### 2.3.6 与PM-Agent的关系

- PM-Agent(L3)在刚性框架之上
- PM-Agent可审批豁免请求
- PM-Agent可查看审计日志
- PM-Agent可调整刚性规则阈值

### 2.4 TODO系统设计

#### 2.4.1 分层设计

```
┌─────────────────────────────────────────────────┐
│  应用层                                          │
│  (编号、来源、模板)                              │
├─────────────────────────────────────────────────┤
│  通信层                                          │
│  (寻址、路由、感知、确认)                        │
├─────────────────────────────────────────────────┤
│  刚性约束层                                       │
│  (依赖强检、自验收阻断、生命周期、审计)           │
└─────────────────────────────────────────────────┘
```

#### 2.4.2 应用层能力（v2.3.1完成）

**参考**: `PROPOSAL_2026-02-026_agent_id_and_role_rename.md` (Agent身份体系)

| 能力 | 说明 |
|------|------|
| 编号系统 | TODO-XtoY-xxx格式，支持多Agent |
| 来源标签 | REQUIREMENT/BUG/FEEDBACK/MANUAL |
| 事件驱动 | 签署后自动创建TODO |
| 模板化 | 不同类型TODO使用不同模板 |

#### 2.4.3 通信层能力（v2.3.1完成）

| 能力 | 依托 | 实现方式 |
|------|------|----------|
| **自动同步** | Git | 所有文档操作自动sync |
| 寻址 | Agent ID | target_agent字段 |
| 路由 | 目录服务 | project_state.yaml Agent注册表 |
| 感知 | Webhook | 文件变更推送 |
| 确认 | Git commit | ACK机制 |
| 状态同步 | Git | 状态文件同步 |
| 可靠传输 | Git | Git本身保证 |

#### 2.4.4 Agent注册与管理

**参考**: `PROPOSAL_2026-02-026_agent_id_and_role_rename.md` (Agent身份体系)

| 功能 | 说明 |
|------|------|
| 自动注册 | 启动时自动注册 |
| 身份识别 | 环境变量或Git config |
| 添加新Agent | 启动时自动发现 |

#### 2.4.4 刚性约束（v2.4完成）

| 约束 | 说明 |
|------|------|
| 依赖强检 | 前置TODO未完成则里程碑不能推进 |
| 自验收阻断 | 创建者不能完成自己创建的TODO |
| 生命周期 | 状态变更必须按状态机流转 |
| 审计日志 | 所有操作记录在audit_log.yaml |

## 4. L3: 管理平台层

### 4.1 PM-Agent设计

#### 4.1.1 核心能力

| 能力 | 输入 | 输出 |
|------|------|------|
| 信息接入 | 任意文本 | 结构化信息 |
| 项目识别 | 信息内容 | 归属项目 |
| 类型分类 | 信息内容 | 需求/BUG/会议/其他 |
| 文档生成 | 结构化信息 | 需求/BUG/会议文档 |
| Git分析 | git log | 进度更新 |
| 进度报告 | 项目数据 | 进度报告 |

#### 4.1.2 技术架构

| 组件 | 技术 |
|------|------|
| 前端 | Vue.js |
| 后端 | FastAPI + Python |
| 数据库 | SQLite |

#### 4.1.3 页面设计

| 页面 | 说明 |
|------|------|
| 信息输入 | 接收所有项目相关信息 |
| 项目列表 | 查看所有项目及状态 |
| 进度总览 | 项目进度可视化 |
| 问题跟踪 | BUG列表和状态 |
| Agent列表 | Agent在线状态 + 红点通知 |

#### 4.1.4 PM-Agent版本

| 版本 | 关键功能 | 依赖oc-collab |
|------|---------|---------------|
| v1.0 | 基础框架 | v2.3.x |
| v1.1 | oc-collab集成（Agent管理、Prompt模板） | v2.3.x |
| v1.2 | Agent通知（微信模式红点）、跨项目查询 | v2.3.3 |

#### 4.1.5 Agent通知模式

采用微信模式解决TODO推送问题：
- PM-Agent维护Agent列表+在线状态
- 收到TODO时显示红点提示
- 用户主动去Agent窗口输入"查看TODO"
- Agent通过 `oc-collab todo list` 拉取自己的TODO
