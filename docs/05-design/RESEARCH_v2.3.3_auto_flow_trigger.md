## 二、TODO自动执行的核心场景

根据与Agent1的讨论（MEETING_20260217），核心问题是：**TODO创建后如何自动推送给目标Agent？**

### 2.1 通知模式对比

| 模式 | 描述 | 自动化程度 | 状态 |
|------|------|------------|------|
| **拉模式** | Agent手动`todo list`查看 | ❌ 手动 | 已有 |
| **推模式(TODO)** | TODO创建后自动推给目标Agent | ✅ 自动 | 待实现 |
| **外部通知** | 推送到邮件/钉钉/飞书 | ✅ 自动 | 待评估 |

### 2.2 TODO生命周期自动触发

| 阶段 | 触发事件 | 自动动作 | 复杂度 |
|------|----------|----------|--------|
| **创建** | Agent1创建TODO | 自动推给Agent2 | 中 |
| **读取** | Agent2执行`todo show` | 自动ACK | ✅ 已实现 |
| **完成** | Agent2标记完成 | 自动通知Agent1确认 | 低 |
| **确认** | Agent1确认 | 自动进入下一阶段 | 高 |

### 2.3 现有基础设施

| 组件 | 功能 | 状态 |
|------|------|------|
| StateNotifier | 发送Webhook通知 | ✅ 已有 |
| StateReceiver | 接收Webhook（Flask服务） | ✅ 已有 |
| agent listen | 轮询检测TODO | ✅ 已有 |
| 自动ACK | `todo show`自动确认 | ✅ 已实现 |
| **自动启动** | Agent启动时自动运行listen | ❌ 缺失 |

## 五、核心问题分析

### 5.1 技术可行性

**低复杂度（可实现）**:
- TODO完成通知：基于现有StateNotifier，监听TODO状态变更
- Bug自动创建TODO：已有AutoBugDetector基础

**中复杂度（需要设计）**:
- 文档签署后自动启动：需要触发详细设计流程
- 开发自检通过创建提测TODO：需要定义"自检通过"的标准

**高复杂度（需深入研究）**:
- 测试用例设计自动触发：涉及多阶段流转
- 评审通过自动进入下一阶段：需要处理人工确认节点

### 5.2 核心风险

| 风险 | 描述 | 应对措施 |
|------|------|----------|
| **Collusion（勾结）** | Agent自己验收自己的代码 | 必须人工确认 |
| **过度自动化** | Agent失去主动思考能力 | 保留人工决策节点 |
| **状态不一致** | 自动触发后状态不同步 | 使用Git作为唯一数据源 |
| **循环触发** | A→B→A无限循环 | 设置触发计数器上限 |

## 六、需要人工干预的节点

根据研究，以下节点必须保留人工干预：

| 节点 | 原因 | 建议方式 |
|------|------|----------|
| 评审完成后 | 需要确认是否进入下一步 | 用户确认弹窗 |
| 验收通过后进入部署 | 避免collusion | Agent1确认 + Agent2执行 |
| 发布前 | 确认版本号、变更内容 | 用户审批 |

## 七、推荐实现方案

### 7.1 分阶段实现

**阶段1：低风险自动化（立即可做）**
- TODO创建自动推给目标Agent（基于StateNotifier）
- Bug发现自动创建修复TODO
- 修复完成自动创建验收TODO

**阶段2：中风险自动化（v2.3.3）**
- 需求签署后自动创建设计TODO
- 开发自检通过自动创建提测TODO

**阶段3：高风险自动化（v2.4+）**
- 评审通过自动推进阶段
- 自动触发测试用例设计

### 7.2 触发机制

| 机制 | 适用场景 |
|------|----------|
| 文件监控 (watch) | TODO状态变更、文件变更 |
| 定时轮询 | Agent在线检测积压TODO |
| Webhook回调 | 外部系统触发 |

### 7.3 实现路线图

```
v2.3.3 (阶段1):
├── TODO创建自动推送
│   ├── StateNotifier增强（支持推给指定Agent）
│   ├── StateReceiver增强（自动启动）
│   └── agent listen自动启动
├── 自动ACK（已实现）
└── Bug自动创建TODO

v2.3.3 (阶段2):
├── 需求签署自动创建设计
└── 开发自检通过创建提测

v2.4+ (阶段3):
├── 评审通过自动推进
└── 测试用例设计自动触发
```

## 九、结论与建议

### 9.1 结论

1. **核心场景明确**: TODO自动推给目标Agent是最高优先级的需求
2. **基础设施已有**: StateNotifier + StateReceiver + agent listen
3. **关键缺失**: 自动启动机制
4. **风险可控**: 只要保留人工干预节点，风险可控制

### 9.2 建议

1. **v2.3.3优先实现**: TODO创建自动推送（基于现有StateNotifier）
2. **明确边界**: 哪些可以自动，哪些必须人工
3. **增量开发**: 不要一次性实现所有功能
