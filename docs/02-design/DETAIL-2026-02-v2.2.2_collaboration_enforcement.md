## 1. 概述

### 1.1 项目背景

oc-collab 是一个双 Agent 协作框架，实现产品经理(Agent1)与开发负责人(Agent2)的分离式协作。v2.2.2 版本聚焦解决协作规范问题，防止 Agent 越权操作和文档状态混乱。

### 1.2 设计范围

| 功能 | 子功能 | 描述 |
|------|--------|------|
| F-PROC-001 | 协作规范强制执行 | |
| | F-PROC-001.1 | 角色边界强制检查 |
| | F-PROC-001.2 | 文档状态阶段绑定 |
| | F-PROC-001.3 | 完整性门禁 |
| F-GIT-001 | Git 同步集成机制 | 集成已有 auto_git_sync.py，非重写 |

### 2.2 合规检查引擎 (Compliance Engine)

#### 职责

统一管理所有合规检查，提供统一的 CLI 入口。

#### 接口

```python
class ComplianceEngine:
    """合规检查引擎"""

    def __init__(self, project_path: str):
        self.project_path = Path(project_path)
        self.role_checker = RoleBoundaryChecker(project_path)
        self.state_binder = DocumentStateBinder(project_path)
        self.completeness_gate = CompletenessGate(project_path)

    def check(self, check_type: str, target: str) -> ComplianceResult:
        """
        执行合规检查

        Args:
            check_type: 检查类型
                - "role_boundary": 角色边界检查
                - "doc_state": 文档状态检查
                - "completeness": 完整性检查
            target: 检查目标路径

        Returns:
            ComplianceResult: 检查结果
        """
        pass

    def check_all(self, target: str) -> List[ComplianceResult]:
        """执行所有合规检查"""
        pass
```

#### 业务流程

```
用户执行操作 (如 oc-collab design create)
    ↓
ComplianceEngine.check("role_boundary", target)
    ↓
RoleBoundaryChecker 检查
    ↓
返回结果: 通过 / 拒绝
    ↓
若拒绝，显示错误消息
```

### 2.3 角色边界检查器 (Role Boundary Checker)

#### 职责

检查 Agent 是否在权限范围内操作，防止越权。

#### 配置

```python
# 角色权限配置
ROLE_PERMISSIONS = {
    "agent1": {
        "allowed_dirs": [
            "docs/01-requirements/",
            "docs/03-test/",
            "docs/04-deployment/",
        ],
        "denied_dirs": [
            "docs/02-design/",
            "src/",
        ],
        "denied_actions": [
            "signoff_own_doc",  # 不能签署自己创建的文档
        ],
    },
    "agent2": {
        "allowed_dirs": [
            "docs/02-design/",
            "src/",
            "tests/",
        ],
        "denied_dirs": [
            "docs/01-requirements/",  # 评审除外
        ],
        "allowed_actions": [
            "review",
        ],
    },
}
```

#### 接口

```python
class RoleBoundaryChecker:

        """
        检查角色边界

        Args:
            agent_id: Agent ID (agent1/agent2)
            action: 操作类型 (create/edit/delete/signoff)
            target: 目标路径

        Returns:
            ComplianceResult: 检查结果
        """
        pass

    def is_denied_dir(self, agent_id: str, path: str) -> bool:
        """检查路径是否被拒绝"""
        pass

    def is_allowed_action(self, agent_id: str, action: str) -> bool:
        """检查操作是否被允许"""
        pass
```

### 2.4 文档状态绑定器 (Document State Binder)

#### 职责

将文档状态与协作流程阶段绑定，防止 DRAFT 文档被评审。

#### 状态机

```python
# 文档状态机
DOCUMENT_STATES = {
    "DRAFT": {
        "transitions": ["REVIEW_PENDING"],
        "agent1_actions": ["edit", "submit_review"],
        "agent2_actions": ["view"],
    },
    "REVIEW_PENDING": {
        "transitions": ["REVIEWED"],
        "agent1_actions": ["view"],
        "agent2_actions": ["review", "signoff"],
    },
    "REVIEWED": {
        "transitions": ["APPROVED"],
        "agent1_actions": ["confirm", "signoff"],
        "agent2_actions": ["view"],
    },
    "APPROVED": {
        "transitions": ["ARCHIVED"],
        "agent1_actions": ["view"],
        "agent2_actions": ["view"],
    },
    "ARCHIVED": {
        "transitions": [],
        "agent1_actions": ["view"],
        "agent2_actions": ["view"],
    },
}
```

```python
    def check_transition(
        self, doc_path: str, target_state: str, agent_id: str
```

#### 识别主文档规则

```python
# 主文档命名规则
MAIN_DOC_PATTERNS = [
    r"requirements_v\d+\.\d+\.md",
    r"design_v\d+\.\d+\.md",
    r"REVIEW_.*\.md",

# 子文档命名规则（不允许单独评审）

    r".*_v\d+\.\d+_[a-z]+\.md",  # 如 requirements_v2.2.2_*.md
```

### 2.6 Git 同步集成器 (Git Sync Integrator)

#### 职责

集成已有的 auto_git_sync.py，在关键节点自动触发同步。

#### 集成点

| 触发点 | 行为 |
|--------|------|
| `oc-collab phase-advance` | 调用 `auto_git_sync.sync_all()` |
| `oc-collab todo done` | 调用 `auto_git_sync.auto_add()` + `auto_commit()` |

#### 接口

```python
class GitSyncIntegrator:
    """Git 同步集成器"""

    def __init__(self, project_path: str):
        self.project_path = Path(project_path)
        self.auto_git_sync = AutoGitSyncEngine(project_path)

    def sync_all(self) -> SyncResult:
        """完整同步 (add + commit + push)"""
        pass

    def sync_state(self) -> SyncResult:
        """同步状态文件 (add + commit)"""
        pass

    def check_unsynced(self) -> List[str]:
        """检查未同步的文件"""
        pass

    def warn_unsynced(self) -> str:
        """生成未同步警告消息"""
        pass
```

#### 错误处理

```python
class SyncError(Exception):
```

## 3. CLI 集成

### 3.1 新增命令

```python
# src/cli/main.py

@main.command()
@click.option("--type", "check_type", type=click.Choice(["role", "state", "completeness"]))
@click.argument("target")
def compliance_check(check_type: str, target: str):
    """合规检查"""
    engine = ComplianceEngine(Path.cwd())
    result = engine.check(check_type, target)
    click.echo(result.message)


@main.command()
def git_sync():
    """Git 同步"""
    integrator = GitSyncIntegrator(Path.cwd())
    result = integrator.sync_all()
    click.echo(result.message)
```

### 3.2 现有命令集成

```python
# phase_advance 集成
@main.command()
def phase_advance():
    """推进阶段"""
    # ... 现有逻辑 ...

    # 新增：Git 同步
    integrator = GitSyncIntegrator(Path.cwd())
    sync_result = integrator.sync_all()
    if not sync_result.success:
        click.echo(f"⚠️ Git 同步失败: {sync_result.message}")


# todo_done 集成
@main.command()
@click.argument("todo_id")
def todo_done(todo_id: str):
    """完成待办"""
    # ... 现有逻辑 ...

    # 新增：Git 同步状态
    integrator = GitSyncIntegrator(Path.cwd())
    unsynced = integrator.check_unsynced()
    if unsynced:
        integrator.sync_state()
        click.echo(f"✅ 待办已更新，状态已同步")
```
