## 3. FR-STATE-001: 状态识别修复

### 3.1 问题描述

StateManager 不支持 v2.2.x 版本化结构，`oc-collab status` 无法正确识别当前版本状态

### 3.2 修复方案

```python
class StateManager:
    """状态管理器"""
    
    def _get_stage_data(self, version: str = None) -> dict:
        """
        获取指定版本的阶段数据
        
        支持:
        - v1.x: stage
        - v2.0.x ~ v2.1.x: design/development/testing
        - v2.2.x: design/development/testing (版本化)
        """
        pass
    
    def _save_stage_data(self, version: str, stage: str, data: dict):
        """
        保存阶段数据到指定版本
        
        写入:
        - v1.x: state[stage] = data
        - v2.0.x ~ v2.1.x: state[stage] = data
        - v2.2.x: state.v2_2[version][stage] = data
        """
        pass
    
    def get_current_version(self) -> str:
        """获取当前版本号"""
        pass
    
    def get_current_stage(self, version: str = None) -> str:
        """获取当前阶段"""
        pass
```

### 6.1 功能描述

**说明**: 明确定义评审优先级，Critical Review 覆盖 Technical Review

### 6.2 Skill更新内容

**Skill**: `oc_collab_collaboration_guide`

**新增章节**: "评审优先级规则"

```markdown
## 评审优先级规则

### 评审类型定义

| 类型 | 说明 | 角色 |
|------|------|------|
| **Technical Review** | 技术可行性评估 | Agent 2 |
| **Critical Review** | 批判性质疑 | Agent 1 或 Agent 2 |

### 优先级规则

```
Critical Review > Technical Review
```

### 评审流程

```
文档提交评审
    │
    ├── Agent 2 执行 Technical Review
    │           │
    │           └── 输出：技术可行性评估
    │                       │
    ├── Agent 1 执行 Critical Review（可选）
    │           │
    │           └── 输出：批判性结论
    │                       │
    └── 最终决策
            │
            └── Critical Review 结论覆盖 Technical Review
                        │
                        └── 一个最终评审结论
```

### 并存处理

当两个评审并存时：
- Critical Review 结论为准
- Technical Review 结论作为参考
- 不允许两个结论矛盾时无裁决

### 签署规范

| 评审类型 | Agent 1 | Agent 2 |
|----------|---------|---------|
| Technical Review | - | "技术评审通过" / "技术评审通过（有条件）" |
| Critical Review | "批判性评审通过（有条件）" / "批判性评审通过" | "批判性评审通过（有条件）" / "批判性评审通过" |
| **最终结论** | **Critical Review 结论为准** | **Critical Review 结论为准** |
```

### 6.3 验收标准

- [ ] 协作规范中明确评审优先级
- [ ] 同一文档只有一个最终评审结论
- [ ] Critical Review 结论覆盖 Technical Review

### 7.3 测试用例示例

```python
def test_owner识别():
    """
    测试文件Owner识别机制
    """
    # 1. Agent1创建文件
    create_file("src/core/test.py", agent="agent1")
    
    # 2. 检查Owner
    owner = get_file_owner("src/core/test.py")
    assert owner == "agent1"
    
    # 3. Agent1修改
    can_modify = can_modify("src/core/test.py", "agent1")
    assert can_modify == True
    
    # 4. Agent2修改（应该拒绝）
    can_modify = can_modify("src/core/test.py", "agent2")
    assert can_modify == False


def test_owner转移():
    """
    测试Owner转移机制
    """
    # 1. Agent1创建文件
    create_file("src/core/test.py", agent="agent1")
    
    # 2. Agent2签署
    sign_document("src/core/test.py", agent="agent2")
    
    # 3. Owner转移给Agent2
    owner = get_file_owner("src/core/test.py")
    assert owner == "agent2"
    
    # 4. Agent2可以修改
    can_modify = can_modify("src/core/test.py", "agent2")
    assert can_modify == True
```
