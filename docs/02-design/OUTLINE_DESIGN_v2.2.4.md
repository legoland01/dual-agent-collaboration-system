## 2. 功能模块关系

### 2.1 调用关系

```
[调用方] → [被调用方] : 说明

Agent → SkillEnforcer : 新Session自动检测Skill
Agent → GitCommit : 执行Git提交操作
GitCommit → SignoffEnforcer : 提交前检查签署状态
Agent → PhaseAdvance : 推进阶段
PhaseAdvance → SignoffEnforcer : 推进前检查签署
Agent → Requirements完整性检查 : 验证需求文档完整性
Agent → ReviewEnforcer : 执行评审锁定
```

### 2.2 数据依赖

| 数据提供方 | 数据使用方 | 数据类型 |
|------------|------------|----------|
| project_state.yaml | 所有模块 | 项目状态 |
| agent_adhoc_todos.yaml | ProjectManager | 任务列表 |
| skills/ | SkillEnforcer | Skill配置 |
| docs/01-requirements/ | Requirements完整性检查 | 需求文档 |

### 2.3 时序关系

| 功能A | → | 功能B | 说明 |
|-------|---|-------|------|
| Skill加载检查 | → | 任意CLI命令 | 先检查Skill |
| 签署状态检查 | → | Git提交 | 先验证签署 |
| 需求完整性检查 | → | 需求评审 | 先验证完整性 |
| 阶段条件检查 | → | 阶段推进 | 先验证前置条件 |
| 评审锁定检查 | → | 状态变更 | 先验证评审结果 |

### 3.2 本版本解决的问题

v2.2.4 核心价值：**从"框架"升级为"系统"**

| 问题 | 解决方案 |
|------|----------|
| Agent在新Session中忘记协作规范 | Skill强制加载检查 |
| Git操作分散，规范不统一 | Git统一提交入口 |
| 里程碑缺失未被发现的系统性缺陷 | 完整性自动检查 |
| 前置条件不满足也能推进阶段 | 阶段推进门槛检查 |
| 评审结论无法强制执行 | 评审结果执行机制 |

## 4. 用户故事/场景

### 4.1 用户故事

| ID | 故事描述 | 验收标准 | 优先级 |
|----|----------|----------|--------|
| US-001 | Agent在新Session中，系统自动检查需要的Skill | 未加载时提示加载命令 | P0 |
| US-002 | Agent执行Git提交时，系统统一规范 | 自动生成commit message，支持强制跳过 | P1 |
| US-003 | Agent提交代码前，系统验证签署是否完整 | 未完整签署则拒绝提交 | P0 |
| US-004 | Agent验证需求文档时，系统自动检查完整性 | 输出缺失项列表 | P0 |
| US-005 | Agent推进阶段时，系统检查前置条件 | 条件不满足时阻止推进 | P0 |
| US-006 | 评审结论为"不通过"时，系统锁定状态 | 锁定状态下无法推进 | P1 |

### 4.2 使用场景

| 场景 | 触发条件 | 主要步骤 | 预期结果 |
|------|----------|----------|----------|
| 新Session开始 | Agent启动新Session | 1. 检测当前阶段<br>2. 加载所需Skill<br>3. 提示未加载的Skill | 提示信息 |
| Git提交代码 | Agent执行提交 | 1. 引导选择变更类型<br>2. 生成commit message<br>3. 验证签署状态<br>4. 执行提交 | 提交成功或拒绝 |
| 验证需求文档 | Agent需要验证 | 1. 执行完整性检查<br>2. 输出缺失项<br>3. 标记问题项 | 完整性报告 |
| 推进阶段 | Agent需要推进 | 1. 检查前置条件<br>2. 验证签署<br>3. 更新状态 | 推进成功或拒绝 |
