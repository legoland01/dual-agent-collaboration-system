## 1. 背景

### 1.1 问题描述

2026-01-31 至 2026-02-06 期间，v2.2.0 发布并修复了多个 BUG，但：

| 问题 | 影响 |
|------|------|
| `COLLABORATION_GUIDE.md` 从未更新 | Agent 无法获知新协作规范 |
| `README.md` 内容过时 | 新用户无法获知最新功能 |
| CHANGELOG.md 手动维护 | 容易遗漏、格式不统一 |

### 1.2 根因分析

```
版本发布 → 文档未同步 → Agent 使用过时信息 → 协作问题
```

### 1.3 解决方案

在 oc-collab 中增加「文档同步检查」质量门禁：
- 发布前自动检查关键文档
- 缺少更新则阻止发布
- 强制要求文档与版本同步

---

## 2. 功能需求

### 2.1 发布前文档检查

**需求编号**: FR-DOC-001

**描述**: 在执行 `oc-collab release` 或推进阶段前，自动检查关键文档是否已更新。

**检查项**:

| 文档 | 检查内容 | 触发条件 |
|------|----------|----------|
| `CHANGELOG.md` | 包含当前版本记录 | release 前 |
| `COLLABORATION_GUIDE.md` | 最后更新日期 >= 最后代码提交日期 | phase_advance 前 |
| `README.md` | 版本号与当前版本一致 | release 前 |

**命令示例**:
```bash
# 手动检查文档同步状态
oc-collab doc check

# 输出示例
=== 文档同步检查 ===

【必须更新】
❌ COLLABORATION_GUIDE.md - 最后更新: 2026-01-31，最后代码提交: 2026-02-06
❌ README.md - 版本信息: v2.2.0，当前版本: v2.2.1

【建议更新】
⚠️ 使用手册.md - 文件不存在

检查未通过，请更新上述文档后再发布。
```

### 2.2 自动提醒机制

**需求编号**: FR-DOC-002

**描述**: 当检测到代码变更但相关文档未更新时，自动提醒 Agent。

**触发场景**:
- 提交代码后
- 推进阶段前
- 执行 release 前

**提醒示例**:
```
⚠️ 检测到代码变更，但 COLLABORATION_GUIDE.md 未更新
建议: 运行 `oc-collab doc check` 检查文档同步状态
```

### 2.3 文档版本追踪

**需求编号**: FR-DOC-003

**描述**: 在 `state/project_state.yaml` 中记录文档版本信息。

**存储格式**:
```yaml
documentation:
  collaboration_guide:
    last_updated: "2026-01-31"
    last_code_commit: "2026-02-06"
    status: "outdated"  # outdated / up_to_date
  changelog:
    version: "v2.2.0"
    status: "outdated"
  readme:
    version: "v2.2.0"
    status: "outdated"
```

### 2.4 跳过检查选项（紧急情况）

**需求编号**: FR-DOC-004

**描述**: 提供 `--force` 选项，允许紧急情况下跳过文档检查。

**命令示例**:
```bash
# 强制发布（不检查文档）
oc-collab release --force

# 警告
⚠️ 警告：跳过文档同步检查
请在紧急发布后 24 小时内更新相关文档。
```
