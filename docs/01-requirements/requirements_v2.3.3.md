## 1. 背景

v2.3.2已完成SQLite存储 + 实时通知交互，v2.3.3规划：
- 自动流程触发：减少人工干预，提升效率
- 测试沙箱：隔离测试数据，保障安全
- 跨项目查询：支持内部子系统信息互通

---

## 2. 目标

确保oc-collab流程可靠 + 自动化流程触发 + 测试数据隔离

## 3. 功能需求

### F-AT-01: 状态变更监听

**需求描述**：监听文档状态变化（签署/评审/验收）

**详细说明**：
1. 监听TODO状态变更
2. 监听需求文档状态变更
3. 监听设计文档状态变更

**外部系统获取变更**（PM-Agent等）：
```bash
# 通过CLI查询变更
oc-collab project <name> changes --since=2026-02-19T10:00:00Z --json

# 返回格式
{"changes": [{"type": "todo", "id": "TODO-1to2-001", "old_status": "pending", "new_status": "completed", "timestamp": "..."}]}
```

**验收标准**：
- [ ] 状态变更事件可捕获
- [ ] 事件包含变更前后状态
- [ ] 支持外部系统通过changes --since查询变更

### F-AT-09b: 与Test-Agent协作

**需求描述**：oc-collab测试沙箱与Test-Agent测试平台的协作关系

**详细说明**：
1. oc-collab v2.3.3提供基础的测试沙箱能力（F-AT-09/10）
2. Test-Agent是独立的测试平台，有自己的测试项目、Agent管理能力
3. 两者关系：
   - oc-collab: 提供基础的SQLite隔离能力
   - Test-Agent: 复用oc-collab的测试沙箱，同时提供更高级的测试管理能力

**协作方式**：
- Test-Agent使用`OC_TEST_DB=1`环境变量调用oc-collab CLI操作测试数据库
- Test-Agent通过跨项目查询API（F-AT-11）获取测试结果
- Test-Agent需要通过权限验证（F-AT-12）才能查询项目信息

**验收标准**：
- [ ] Test-Agent可使用环境变量调用oc-collab测试功能
- [ ] 跨项目查询API支持Test-Agent调用
- [ ] 权限控制生效

**参考**：
- Test-Agent需求: `../test-agent/docs/01-requirements/requirements_v1.0.md`
- Test-Agent评审意见: `../test-agent/docs/02-design/REVIEW_v1.0_by_Agent1.md`

### F-AT-11: 跨项目信息查询

**需求描述**：支持内部子系统查询其他项目状态/TODO

**详细说明**：
1. 查询其他项目的TODO
2. 查询项目状态
3. 查询项目文档

**CLI接口设计**：

```bash
# 查询项目状态 - 返回结构化JSON
oc-collab project <name> status --json

# 期望返回格式
{
  "project": "金融法院",
  "requirements": {"total": 10, "completed": 5, "draft": 3, "review": 2},
  "bugs": {"total": 3, "resolved": 2, "open": 1},
  "todos": {"pending": 2, "in_progress": 1, "completed": 5},
  "last_updated": "2026-02-19T10:00:00Z"
}

# 查询项目TODO - 支持过滤
oc-collab project <name> todos --json --status=completed

# 查询项目变更（用于PM-Agent轮询）
oc-collab project <name> changes --since=2026-02-19T10:00:00Z --json
# 返回: {"changes": [{"type": "todo", "id": "TODO-1to2-001", "old_status": "pending", "new_status": "completed", "timestamp": "..."}]}

# 查询项目进度（用于Dashboard）
oc-collab project <name> progress --json
# 返回: {"project_name": "金融法院", "progress": 65, "milestones": [...]}
```

**验收标准**：
- [ ] 跨项目查询命令
- [ ] 返回项目信息
- [ ] 支持--json格式输出
- [ ] 支持--since参数查询变更
- [ ] 支持progress命令查询进度

**需求描述**：oc-collab docs query/list/architecture

3. 文档格式要求：Markdown
4. 文档命名规范：`{类别}_{名称}.md`

### A.8 关键实现原则

1. **循环类**：自动触发下一次流程，无需人工干预
2. **预警类**：自动检测 + 通知，需人工确认后继续
3. **签署类**：必须人工确认，自动化仅做通知和流程推进
