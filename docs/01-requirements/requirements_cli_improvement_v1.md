## 1. 变更概述

### 1.1 背景
当前双Agent协作框架CLI需要用户手动切换Agent、监控状态、执行操作，无法实现零干预自动协作。用户期望启动命令后，CLI能够自动检测状态并执行当前阶段应该做的事情。

### 1.2 目标
实现零干预自动协作模式：
- 用户只需运行 `oc-collab auto`
- CLI自动检测当前状态
- CLI自动执行当前Agent应该做的操作
- CLI自动处理协作流程直到完成

### 1.3 范围
新增三个命令：
- `oc-collab auto` - 自动执行当前任务
- `oc-collab todo` - 显示待办事项
- `oc-collab work` - 智能工作流引导

## 6. 风险评估

| 风险 | 可能性 | 影响 | 应对措施 | 监控 |
|-----|:------:|:----:|---------|------|
| auto命令进入死循环 | 低 | 高 | max-iterations=10限制 | 日志记录迭代次数 |
| 锁文件残留导致无法执行 | 中 | 中 | 启动时检查残留锁文件并清理 | 锁文件时间戳检查 |
| todo命令显示信息不完整 | 中 | 低 | 覆盖所有阶段和状态组合 | 单元测试覆盖 |
| work命令建议不准确 | 中 | 低 | 基于状态机规则生成建议 | 人工审核建议规则 |
| 两个Agent同时执行auto冲突 | 低 | 中 | 锁文件机制+执行前检查 | 锁文件互斥检测 |

### 6.1 风险应对详细方案

#### R1: 死循环防护
- **预防**: max-iterations=10，达到后自动退出
- **恢复**: 显示"达到最大迭代次数，建议检查协作状态"
- **监控**: 每次迭代记录日志

#### R2: 锁文件残留
- **预防**: 正常退出和用户中断时删除锁文件
- **恢复**: 启动时检查锁文件时间戳，超过1小时自动清理
- **监控**: 记录锁文件创建和删除时间

#### R3: 信息显示不完整
- **预防**: 单元测试覆盖所有阶段×状态组合
- **恢复**: 发现缺失显示项时补充代码
- **监控**: 测试覆盖率100%

#### R4: 建议不准确
- **预防**: 基于状态机规则生成，规则文档化
- **恢复**: 人工审核建议规则，定期优化
- **监控**: 收集用户反馈

#### R5: 冲突处理
- **预防**: 锁文件机制防止同时运行
- **恢复**: 检测到冲突时提示"另一个实例正在运行"
- **监控**: 锁文件状态检查

## 7. 工作流程

### 7.1 auto 命令执行流程
```
1. 同步远程变更
2. 检测当前状态（阶段、签署状态）
3. 判断当前Agent角色
4. 根据角色执行操作：
   - Agent 1: 创建文档、签署、评审
   - Agent 2: 评审、修复、签署、测试
5. 自动Git提交推送
6. 检查是否完成：
   - 未完成: 回到步骤1
   - 已完成: 退出并报告结果
```

### 7.2 状态机增强
```
当前状态 → 应该做什么 → 执行什么命令

project_init → 初始化 → init
requirements_draft → 创建需求文档 → 提示用户
requirements_review → 评审需求 → review --new + signoff
requirements_approved → 进入设计阶段 → 提示用户
design_review → 评审设计 → review --new + signoff
development → 开发修复 → 修复 + 测试
testing → 测试验证 → signoff
completed → 无操作 → 退出
```

## 10. 评审回复

### 10.1 死循环防护机制

**Agent 2 问题**: 最大循环次数、退出条件、中断方式未定义

**Agent 1 回复**:
- **最大循环次数**: 10次
- **退出条件**: `phase == "completed"` 或用户按 `Ctrl+C` 中断
- **中断处理**: 捕获 KeyboardInterrupt，显示 "用户中断，状态已保存"

### 10.2 权限和提交信息

**Agent 2 问题**: 哪个Agent可以使用auto命令，提交信息如何生成

**Agent 1 回复**:
- **权限**: 两个Agent都可以使用 `auto` 命令
- **提交信息格式**: `feat(auto): 自动协作执行 - {时间戳}`
- **提交时机**: 每次状态变更后自动提交

### 10.3 冲突处理

**Agent 2 问题**: 两个Agent同时运行auto命令会发生冲突

**Agent 1 回复**:
- **冲突预防**: `auto` 命令启动时先检查 `git status`
  - 有本地修改未提交: 提示用户先执行 `git add` 和 `commit`
  - 检测到远程有更新: 自动执行 `git pull`
- **执行时锁定**: 创建一个 `.auto_lock` 文件标记运行状态
