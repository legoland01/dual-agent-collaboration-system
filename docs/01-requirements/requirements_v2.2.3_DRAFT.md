## 2. 功能需求

### 2.1 REQ-CONTEXT-001 + REQ-INIT-001: .a 文件机制（已合并）

**原始文档**: requirements_v2.2.3_AutoContext.md

**概述**: 通过 `.a` 文件实现 Agent 上下文自动恢复和智能初始化。

| 功能 | 说明 |
|------|------|
| .a 文件 | 用户说"你是 agent1"，AI 自动读取 .a 文件 |
| oc-collab init 智能初始化 | 检测 .a 存在则跳过，不存在则创建 .a, docs/, state/ |

**验收标准**:
- [ ] 用户输入"你是 agent1"后，AI 自动读取 `.a` 文件
- [ ] oc-collab init 检测 .a 存在则跳过初始化
- [ ] oc-collab init 未检测到 .a 则创建 .a, docs/, state/
- [ ] 用户只需记住一句话，无需记住文件名

**工时**: 5h

---

### 2.2 F-AUTO-002: 任务状态自动同步

**原始来源**: requirements_v2.2.2_READY.md

**描述**: todowrite / todoedit 操作后自动同步到文件。

**验收标准**:
- [ ] `todowrite` / `todoedit` 操作后自动同步到文件
- [ ] 同步时有明确提示（"✓ 已同步到文件"）
- [ ] 支持查看同步历史

**工时**: 2h

---

### 2.3 F-REVIEW-001: 动态评审 Checklist（含逆向验证）

**原始来源**: requirements_v2.2.2_READY.md

**核心洞察**: 评审流于形式，只"确认"不"质疑"。

**逆向检查项**:
| 序号 | 检查项 | 目的 |
|------|--------|------|
| REV-001 | "这份文档是否忽略了什么重要因素？" | 强制寻找遗漏 |
| REV-002 | "如果你是另一个角色，你会怎么批评这个设计？" | 强制换位思考 |
| REV-003 | "这个方案的最大风险是什么？如何缓解？" | 强制风险评估 |
| REV-004 | "有哪些替代方案？为什么当前方案是最好的？" | 强制对比分析 |

**验收标准**:
- [ ] 评审时自动生成逆向检查项（≥50%）和正向检查项
- [ ] 强制 Agent 先完成逆向检查项，且必须全部完成
- [ ] 逆向检查项回答长度 ≥ 50 字

**工时**: 4-6h

---

### 2.4 F-AUTO-001: 部署发布自动化

**原始来源**: requirements_v2.2.2_READY.md

**描述**: 支持 deployment.yaml 配置发布流程。

**验收标准**:
- [ ] 支持 `deployment.yaml` 配置文件
- [ ] 支持 `oc-collab deployment configure` 交互式配置
- [ ] `oc-collab phase-advance --deploy` 时自动执行发布命令
- [ ] 发布前显示预览，确认后执行

**工时**: 2-4h

---

### 2.5 F-AUTO-003: 测试覆盖率门禁

**原始来源**: requirements_v2.2.2_READY.md

**描述**: 新代码提交时，强制检查单元测试覆盖率不低于阈值。

**验收标准**:
- [ ] 新代码的单元测试覆盖率 ≥ 80%
- [ ] 覆盖率不达标时阻止合并
- [ ] 支持自定义阈值

**工时**: 2-4h

---
