## 1. 概述

### 1.1 版本信息

| 项目 | 值 |
|------|-----|
| 前置版本 | v2.2.11 |
| 变更类型 | 功能增强 |
| 版本目标 | 完成v2.2版本最后一个功能：部署自动化 |

### 1.2 背景

v2.2版本目标：实现稳定可靠的双Agent协作框架

```
v2.2核心功能:
├── Agent独立TODO编号 (v2.2.11) ✅
├── Skill强制执行CLI钩子 (v2.2.11) ✅
├── StateNotifier Receiver (v2.2.11) ✅
└── 部署自动化 (v2.2.12) ⏳
```

### 1.3 问题描述

当前部署流程（oc_collab_deployment_guide）依赖手动执行多个步骤：
1. 文档同步（CHANGELOG.md、README.md）
2. 版本号升级（pyproject.toml）
3. 构建包（python -m build）
4. PyPI上传（twine upload）
5. Git推送（commit、tag、push）
6. 验证发布（API验证、安装测试）
7. 更新项目状态（project_state.yaml）

**痛点**：
- 步骤繁琐，容易遗漏或顺序错误
- 缺乏自动化验证
- 部署后状态更新不及时
- 依赖记忆执行，容易出错

### 1.4 核心原则

| 原则 | 说明 |
|------|------|
| 范围控制 | 本版本聚焦1个核心功能（部署自动化），总工时 ≤ 12h |
| CLI边界 | 只做CLI能做的事情，符合oc-collab工具边界 |
| 用户体验 | 一键部署，减少用户记忆负担 |
| 安全优先 | 敏感操作（PyPI Token）不写入代码，自动提示 |

## 2. 功能需求

### 2.1 F-DEPLOY-001: 部署自动化CLI

**来源**: F-AUTO-001 (历史推迟功能，4次推迟)

**描述**: 提供`oc-collab deploy`命令，实现部署全流程自动化

**功能范围**:
1. 部署前检查（文档同步、测试状态）
2. 版本号管理
3. 包构建
4. PyPI发布
5. Git推送
6. 发布验证
7. 项目状态更新

**验收标准**:

**部署前检查**:
- [ ] 命令执行时自动检查文档同步状态（CHANGELOG.md、README.md）
- [ ] 自动检查测试验收状态（testing.status: APPROVED）
- [ ] 如检查未通过，提示具体缺失项并退出

**版本号管理**:
- [ ] 支持 `--version` 参数手动指定版本号
- [ ] 如未指定，自动读取当前版本并提示用户确认
- [ ] 自动更新 pyproject.toml 中的版本号

**包构建**:
- [ ] 自动清理旧的构建文件（dist/、build/、*.egg-info/）
- [ ] 自动执行 `python -m build`
- [ ] 验证构建产物存在（.whl、.tar.gz）

**PyPI发布**:
- [ ] 自动执行 `twine upload dist/*`
- [ ] 捕获并显示上传结果
- [ ] 处理"File already exists"错误（版本号冲突）

**Git推送**:
- [ ] 自动执行 `git add pyproject.toml`
- [ ] 自动生成提交信息（格式: `release: v{x}.{y}.{z}`）
- [ ] 自动创建版本标签（格式: `v{x}.{y}.{z}`）
- [ ] 自动推送到远程仓库
- [ ] 支持dry-run模式（预览而不执行）

**发布验证**:
- [ ] 自动调用PyPI API验证包已发布
- [ ] 显示验证结果（版本号、包名、文件列表）
- [ ] 可选：pip安装测试

**项目状态更新**:
- [ ] 自动更新 `state/project_state.yaml` 中的部署状态
- [ ] 记录部署时间、版本号、PyPI URL

**CLI接口**:
- [ ] `oc-collab deploy` - 执行完整部署流程
- [ ] `oc-collab deploy --dry-run` - 预览模式，不执行实际变更
- [ ] `oc-collab deploy --version 2.2.12` - 指定版本号
- [ ] `oc-collab deploy --skip-git` - 跳过Git推送步骤
- [ ] `oc-collab deploy --skip-pypi` - 跳过PyPI上传步骤
- [ ] `oc-collab deploy --verify-only` - 仅执行验证（用于手动部署后验证）

**错误处理**:
- [ ] 每个步骤失败时显示具体错误信息
- [ ] 支持 `--verbose` 参数输出详细日志
- [ ] 部署失败时保留现场，便于排查

**工时**: 8h
