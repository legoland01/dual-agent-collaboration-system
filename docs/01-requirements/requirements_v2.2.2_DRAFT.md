## 1. 概述

### 1.1 版本信息

| 项目 | 值 |
|------|-----|

| 上一版本 | v2.2.1.post1 |
| 变更类型 | 自动化增强 + 协作机制改进 |

### 1.2 变更动机

v2.2.1 发布后，发现以下问题需要解决：

| 问题来源 | 问题描述 | 严重程度 | 解决方案 |
|----------|----------|----------|----------|
| Agent2 反思 | P9: 评审流于形式，只"确认"不"质疑" | P1 | 动态评审 Checklist + 逆向验证 |
| Agent1 反思 | 不知道如何发布到 PyPI | P1 | 部署发布自动化 |
| 协作实践 | todowrite 只更新内存不同步 | P1 | 任务状态自动同步 |

| 协作实践 | docs/ 目录版本混乱 | P2 | 文档版本管理 |
| 协作实践 | Session 重启需重新解释 oc-collab 规则 | P1 | Agent 身份自动识别 |

### 1.3 主要变更

1. **动态评审 Checklist**: 引入逆向验证机制，解决评审流于形式问题
2. **部署发布自动化**: 支持 deployment.yaml 配置和自动发布
3. **任务状态自动同步**: todowrite 自动同步到文件
4. **测试覆盖率门禁**: 新代码提交强制检查覆盖率 ≥ 80%
5. **文档版本管理**: 清晰标识当前版本，不删除历史记录
6. **Agent 身份自动识别**: Session 启动自动加载对应规则和欢迎消息

## 2. 功能需求

### 2.1 F-REVIEW-001: 动态评审 Checklist（含逆向验证机制）

**需求编号**: FR-REVIEW-001

**核心洞察（Agent2 发现）**:
P9 问题的本质是"上下文混同"而非能力问题。Agent2 与 Agent1 共享过多上下文，失去了独立评审视角。解决方案不是简单的 checklist，而是**逆向验证机制**：强制 Agent 从"批判"角度审视文档，而非"确认"角度。

#### 2.1.1 逆向检查项

**描述**: 评审时自动生成逆向检查项，强制 Agent 从批判角度审视文档。

| 序号 | 逆向检查项 | 目的 |
|------|-----------|------|
| REV-001 | "这份文档是否忽略了什么重要因素？" | 强制寻找遗漏 |
| REV-002 | "如果你是另一个角色，你会怎么批评这个设计？" | 强制换位思考 |
| REV-003 | "这个方案的最大风险是什么？如何缓解？" | 强制风险评估 |
| REV-004 | "有哪些替代方案？为什么当前方案是最好的？" | 强制对比分析 |
| REV-005 | "这个实现细节是否经得起推敲？" | 强制细节审视 |

#### 2.1.2 正向检查项

**描述**: 评审时自动生成正向检查项，确保基本质量。

| 序号 | 正向检查项 | 目的 |
|------|-----------|------|
| POS-001 | 功能完整性 | 确保覆盖所有需求 |
| POS-002 | 技术可行性 | 确保技术方案可行 |
| POS-003 | 文档规范性 | 确保格式规范 |

#### 2.1.3 验收标准

- [ ] 评审需求文档时，自动生成逆向检查项（≥50%）和正向检查项
- [ ] 评审设计文档时，自动生成逆向检查项（≥50%）和正向检查项
- [ ] 强制 Agent **先完成逆向检查项**，且必须全部完成
- [ ] 逆向检查项回答长度 ≥ 50 字，且包含实质性质疑内容
- [ ] 正向检查项作为补充，确保基本质量

### 2.2 F-AUTO-001: 部署发布自动化

**需求编号**: FR-AUTO-001

#### 2.2.1 deployment.yaml 配置

**描述**: 支持在项目根目录创建 deployment.yaml 配置文件。

**配置格式**:
```yaml
deployment:
  type: python_pypi
  commands:
    build: python3 -m build
    upload: python3 -m twine upload dist/*
  conditions:
    - phase: deployment
```

#### 2.2.2 交互式配置

**描述**: 支持 `oc-collab deployment configure` 交互式配置。

**命令格式**:
```bash
oc-collab deployment configure
```

**交互流程**:
1. 选择部署类型（PyPI / Docker / NPM / Custom）
2. 输入构建命令
3. 输入上传/发布命令
4. 确认配置

#### 2.2.3 自动发布

**描述**: `oc-collab phase-advance` 时自动执行发布命令。

**命令格式**:
```bash
oc-collab phase-advance --deploy
```

#### 2.2.4 验收标准

- [ ] 支持 `deployment.yaml` 配置文件
- [ ] 支持 `oc-collab deployment configure` 交互式配置
- [ ] `oc-collab phase-advance` 时自动执行发布命令（需 --deploy 选项）
- [ ] 发布前显示预览，确认后执行

### 2.3 F-AUTO-002: 任务状态自动同步

**需求编号**: FR-AUTO-002

#### 2.3.1 自动文件同步

**描述**: todowrite / todoedit 操作后自动同步到文件。

**命令格式**:
```bash
oc-collab todo add "新任务" --agent agent1
oc-collab todo done 1
oc-collab todo edit 1 --status in_progress
```

**行为**:
1. 执行 todowrite / todoedit 操作
2. 自动更新 state/agent_adhoc_todos.yaml
3. 显示同步确认

#### 2.3.2 验收标准

- [ ] `todowrite` / `todoedit` 操作后自动同步到文件
- [ ] 同步时有明确提示（"✓ 已同步到文件"）
- [ ] 支持查看同步历史

### 2.4 F-AUTO-003: 测试覆盖率门禁

**需求编号**: FR-AUTO-003

#### 2.4.1 覆盖率检查

**描述**: 新代码提交时，强制检查单元测试覆盖率不低于阈值。

**命令格式**:
```bash
oc-collab check coverage --threshold 80
```

**行为**:
1. 运行单元测试
2. 计算覆盖率
3. 对比阈值
4. 不达标时阻止合并

#### 2.4.2 验收标准

- [ ] 新代码的单元测试覆盖率 ≥ 80%
- [ ] 覆盖率不达标时阻止合并
- [ ] 支持自定义阈值
- [ ] 显示覆盖率报告

### 2.6 F-IDENTITY-001: Agent 身份自动识别与 Session 启动引导

**需求编号**: FR-IDENTITY-001

#### 2.6.1 身份识别

**描述**: 新 Session 启动时，自动识别 Agent 身份并加载对应规则。

**触发条件**:
- 环境变量 `OC_AGENT_ID=agent1`
- 环境变量 `OC_AGENT_ID=agent2`

**行为**:
1. 读取环境变量 `OC_AGENT_ID`
2. 加载对应的 skill 文件
3. 应用对应的规则

#### 2.6.2 Skill 文件说明

**描述**: Agent 身份识别需要配套的 skill 文件。

**Skill 目录结构**:
```
skills/
├── oc_collab_collaboration_guide/
│   ├── skill.json          # 元数据
│   └── content.md          # 通用协作规范
├── oc_collab_agent1/
│   ├── skill.json
│   └── content.md          # Agent1 专用职责
└── oc_collab_agent2/
    ├── skill.json
    └── content.md          # Agent2 专用职责
```

**验收标准**:
- [ ] skill.json 包含 `agent_id`, `triggers`, `permissions`, `responsibilities`
- [ ] content.md 包含角色职责、工作流程、常用命令
- [ ] 根据 `OC_AGENT_ID` 自动加载对应 skill

#### 2.6.3 欢迎消息

**描述**: Agent 进入项目时，自动显示欢迎消息。

**消息内容**:
- 项目名称
- 当前阶段
- 版本
- Agent 角色
- 待办任务
- 下一步建议

**命令格式**:
```bash
oc-collab start
```

**输出示例**:
```
=== 欢迎使用 OC-Collab ===

项目: oc-collab
当前阶段: development
版本: v2.2.2

你的角色: Agent 2

待办任务 (2 项):
1. [P0] 实现 F-REVIEW-001 - pending
2. [P1] 实现 F-AUTO-001 - pending

下一步: oc-collab todo 查看详情
```

#### 2.6.4 协作指南摘要

**描述**: 显示协作指南摘要，提供完整指南入口。

**内容**:
- 角色职责
- 工作流程
- 常用命令

#### 2.6.5 验收标准

- [ ] 环境变量 `OC_AGENT_ID` 正确识别 Agent 身份
- [ ] 自动加载对应 skill 文件
- [ ] skill.json 和 content.md 符合约定格式
- [ ] `oc-collab start` 命令可用
- [ ] 欢迎消息包含：项目名称、阶段、版本、角色、待办、下一步
- [ ] 显示协作指南摘要，提供完整指南入口
