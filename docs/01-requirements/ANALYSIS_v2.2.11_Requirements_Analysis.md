## 核心问题澄清

### 问题1: P-004 vs P-007 是否解决同一个问题？

**结论**: **是的，应该合并**

| 提案 | 目标 | 具体实现 |
|------|------|----------|
| **P-004 Compliance Agent** | 确保Agent遵循规范 | Skill遵循检查、角色分工检查 |
| **P-007 Skill强制执行** | CLI命令强制检查Skill | todowrite/signoff强制检查 |

**关系**: P-007是P-004的**具体实现之一**

### 问题2: P-003 vs P-005 是否解决同一个问题？

**结论**: **是的，P-003依赖P-005**

| 提案 | 目标 | 依赖 |
|------|------|------|
| **P-003 Agent协作增强** | Skill热更新、新TODO通知 | 需要P-005 |
| **P-005 StateNotifier Receiver** | StateNotifier接收器 | 无 |

**关系**: P-005是P-003的**基础设施**

### 问题3: 为什么P-005被推迟？

**原分析**: "非核心功能"

**实际**: **P-005非常重要**，没有接收器，notification没用

**决策**: **应该纳入v2.2.11**

## 五、关键关系澄清

### 5.1 P-004 与 P-007 的关系

```
P-004 Compliance Agent（目标）
    │
    ├── Skill遵循检查 → P-007 Skill强制执行CLI钩子（实现）
    ├── 角色分工检查 → 新功能：角色合规检查
    └── 合规率追踪 → 新功能：合规统计
```

**决策**: P-004和P-007合并，P-007扩展为"Skill强制执行+Compliance"

### 5.2 P-003 与 P-005 的关系

```
P-003 Agent协作增强（目标）
    │
    ├── Skill热更新 → 需要P-005
    ├── 新TODO通知 → 需要P-005
    └── Agent间通信 → 需要P-005

P-005 StateNotifier Receiver（基础设施）
    │
    ├── HTTP接收器 → 接收Webhook通知
    ├── 消息队列 → 存储待处理通知
    └── 启动自检 → Agent启动时检查未读通知
```

**决策**: P-005必须先做，P-003依赖P-005
