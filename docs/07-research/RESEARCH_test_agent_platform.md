## 一、背景

### 1.1 问题来源

| Bug ID | 问题描述 | 根因 |
|--------|----------|------|
| BUG-20260218-001 | 测试数据丢失：测试脚本直接清空生产数据库 | 缺少独立测试环境 |
| BUG-20260218-003 | Agent身份迷失：测试中频繁切换ID导致身份错乱 | 缺少独立测试Agent |

### 1.2 当前测试困境

- **oc-collab**: CLI 工具，有 E2E 测试
- **PM-Agent**: 有 Vue 前端 + FastAPI 后端
- **问题**: 两个系统测试都在生产环境执行，数据和身份无法隔离

## 二、测试需求分析

### 2.1 测试类型

| 系统 | 后端测试 | 前端测试 | E2E测试 |
|------|---------|---------|---------|

| 痛点 | 影响 |

## 三、核心问题分析 ⭐

### 3.1 多Agent互动测试 ⭐ 最高优先级

**问题**: 如何模拟 Agent1 ↔ Agent2 的真实互动？

**重要性**: 
- TODO 系统核心场景就是多Agent互动
- 跨项目 TODO (PM-Agent ↔ oc-collab) 依赖此能力
- 推迟将导致后续测试负担极大

#### 3.1.2 测试平台配置要求

基于上述场景，测试平台需要支持**动态配置的测试项目**，不固定绑定到任何系统。

**1. 动态测试项目（可配置）**

| 配置项 | 数量 | 说明 |
|--------|------|------|
| 测试项目数量 | ≥4 | 根据测试场景动态分配 |
| 项目类型 | 任意 | 可配置为 oc-collab 项目、PM-Agent 项目、或任意客户项目 |
| 项目关系 | 可配置 | 支持跨项目依赖、并行、串行等关系 |

**示例配置**：
```yaml
test_projects:
  - name: "卷宗系统测试项目"
    type: "oc-collab"  # 或 "pm-agent", "custom"
    repo: "test-repo-dossier"
  - name: "智能环评测试项目" 
    type: "pm-agent"
    repo: "test-repo-env"
  - name: "金融法院测试项目"
    type: "oc-collab"
    repo: "test-repo-court"
  # 更多项目按需添加
```

**2. 测试Agent（动态分配）**

| Agent | 说明 |
|-------|------|
| TestAgent1~N | 可动态分配到任意测试项目 |
| Agent角色可配置 | 产品、开发、测试等角色 |
| 支持Agent池 | 按需启动/停止Agent进程 |

**3. 测试仓库**

| 仓库 | 说明 |
|------|------|
| test-repo-{project_name} | 按需创建，绑定到对应测试项目 |

**4. 测试数据库**

| 数据库 | 说明 |
|--------|------|
| todos_test.db | oc-collab 测试数据（按项目隔离） |
| pm_agent_test.db | PM-Agent 测试数据（按项目隔离） |
| 支持命名空间 | 测试数据按项目前缀隔离 |

**5. 通信机制**

| 机制 | 用途 |
|------|------|
| 文件消息队列 | Agent间同步通信 |
| Webhook Mock | 任意系统间集成测试 |
| 状态变更监听 | 自动化流程触发测试 |

---

#### 3.1.3 方案选择

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| A. 多进程 | 真实环境 | 资源占用大 | S-001 ~ S-006, S-010 ~ S-014 |
| B. 单进程模拟 | 资源占用小 | 无法验证真实通信 | 快速单元测试 |
| C. 消息队列 | 接近真实 | 需要搭建 | S-020 ~ S-022 |

**建议**: **方案 A + B 混合**
- 核心场景（S-001, S-010, S-011）：用多进程
- 快速验证场景：用单进程模拟

### 3.2 前端测试

**问题**: PM-Agent 使用 Vue 前端，需要浏览器环境

**现实情况**: PM-Agent 已有 Vue 测试环境（Vitest），可直接复用

| 方案 | 工具 | 说明 |
|------|------|------|
| A. Puppeteer/Playwright | 真实浏览器 | 可后期引入 |
| B. Vitest + Vue Test Utils | 组件单元测试 | PM-Agent 已有，直接复用 |

**建议**: **方案 B**，v1.0 直接复用 PM-Agent 现有测试

### 3.3 多系统集成测试

**问题**: oc-collab + PM-Agent 同时运行，如何搭建环境？

| 方案 | 说明 |
|------|------|
| A. Docker Compose | 各服务容器化编排 |
| B. 独立进程 | 本地启动多个进程 |
| C. Mock服务 | 用 Mock 替代外部依赖 |

**建议**: 初期用方案 B，后期用方案 A

### 3.4 测试数据管理

**问题**: 每个系统有独立测试数据库，还是共享？

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 独立数据库 | 隔离好 | 数据初始化复杂 |
| B. 共享数据库 | 简单 | 隔离差 |
| C. 命名空间 | 隔离+简单 | 需要数据库支持 |

**建议**: 方案 A，测试前初始化，测试后清理

### 3.5 测试Agent通信

**问题**: 测试Agent之间如何传递消息？

| 方案 | 说明 |
|------|------|
| A. 真实WebSocket | 需要启动通知服务 |
| B. 文件消息队列 | 简单，但延迟高 |
| C. 内存模拟 | 最简单，无法验证真实通信 |

**建议**: 初期用方案 C，后期用方案 A

## 四、Test-Agent 子系统设计

### 4.1 定位

独立于 oc-collab 和 PM-Agent 的测试平台，可被多个子系统复用。

### 4.2 架构

```
┌─────────────────────────────────────────┐
│           Test-Agent (v1.0)             │
├─────────────────────────────────────────┤
│  测试Agent池   │  独立数据库   │  场景管理  │
├─────────────────────────────────────────┤
│  CLI测试执行   │  前端测试执行 │  E2E执行   │
└─────────────────────────────────────────┘
         ↑              ↑              ↑
         │              │              │
    oc-collab       PM-Agent      其他系统
```

### 4.3 核心功能

| 功能 | 说明 | 优先级 | 场景依赖 |
|------|------|--------|----------|
| 独立测试数据库 | state/todos_test.db | P0 | - |
| **动态测试项目配置** | 支持任意数量/类型的测试项目 | P0 ⭐ | S-006, S-014, S-021 |
| **动态测试Agent** | 可分配到任意项目，支持进程池 | P0 ⭐ | S-001~S-014 |
| **多进程Agent执行** | 并行启动多个Agent进程 | P0 ⭐ | S-001~S-014 |
| **测试仓库动态绑定** | 按需创建，绑定到测试项目 | P0 | S-005, S-010 |
| 测试数据隔离 | 按项目/命名空间隔离 | P0 | - |
| Webhook Mock | 任意系统间集成测试 | P1 | S-010~S-014 |
| 测试场景管理 | 定义/执行/记录测试场景 | P1 | S-020~S-022 |
| CLI测试执行 | oc-collab CLI测试 | P1 | - |
| **前端测试执行**PM-Agent现有 | **复用Vitest** | **P1** | **v1.0直接集成** |
| E2E测试执行 | 多系统集成测试 | P2 | S-020~S-022 |

## 七、研究结论

1. **Test-Agent 作为独立子系统是必要的**
   - 解决测试数据隔离问题
   - 支持多类型测试（后端/前端/E2E）
   - 可被 oc-collab 和 PM-Agent 共用

2. **v1.0 最高优先级：多Agent互动测试** ⭐
   - 跨项目 TODO 依赖此能力
   - 不能推迟到 v1.2
   - 直接实现多进程方案

3. **v1.0 必须支持的测试配置（动态化）**
   - **动态测试项目**: 任意数量/类型，不固定绑定到某个系统
   - **动态测试Agent**: 可分配到任意项目，支持进程池
   - **测试仓库动态绑定**: 按需创建
   - **测试数据隔离**: 按项目/命名空间隔离
   - **通信机制**: 文件消息队列 + Webhook Mock
