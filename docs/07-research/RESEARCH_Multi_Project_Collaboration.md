## 一、研究背景与目标

### 1.1 研究背景

当前存在三个项目需要统一管理：
- **oc-collab**：CLI开发框架（L1核心）
- **PM-Agent**：项目管理系统（L3管理平台）
- **financial**：金融案件生成系统

这三个项目之间存在潜在的关联关系，需要研究如何统一管理。

### 1.2 研究目标

1. 定义多项目协作的问题架构
2. 明确oc-collab的服务边界
3. 规划PM-Agent的管理中心功能
4. 验证研究结论的可行性

### 1.3 研究方法

- 现状分析：分析现有三个项目的实际情况
- 问题推导：从实际场景中提取问题
- 理论验证：用软件工程方法论补充

## 七、问题域3：Session启动机制

### 7.1 当前Session管理现状

**oc-collab的Session管理**：
- 通过 `oc-collab switch <agent_id>` 切换Agent身份
- 状态保存在 `state/project_state.yaml`
- 关键字段：`current_agent`

**当前state文件结构**：
```yaml
current_agent: agent1
agents:
  agent1:
    role: PRODUCT_MANAGER
    status: active
  agent2:
    role: DEVELOPMENT_LEAD
    status: active
```

### 7.2 Session启动的问题

**问题清单**：

1. **手动切换**
   - 需要手动执行 `oc-collab switch 1` 或 `oc-collab switch 2`
   - 操作繁琐，容易忘记

2. **多项目切换**
   - 如果同时参与多个项目，如何切换项目？
   - 当前只支持切换Agent身份，不支持切换项目

3. **上下文恢复**
   - Session重启后，如何恢复之前的上下文？
   - 当前只保存current_agent，不保存任务进度

4. **自动化需求**
   - PM-Agent能否自动生成启动提示词？
   - 每次都需要手动告知Agent身份和项目信息

### 7.3 用项目验证

**场景1：Agent从oc-collab切换到PM-Agent**

当前操作：
1. 关闭当前终端
2. 打开新终端
3. cd到pm-agent目录
4. 手动告知Agent身份

问题：
- 能否自动化这个过程？
- PM-Agent能否记住Agent上次的状态？

**场景2：Session重启**

当前状态：
- Agent1正在做TODO-1-387
- Session关闭
- 下次如何恢复？

当前解决方案：
- 状态保存在 `agent_adhoc_todos.yaml`
- 但需要手动加载上下文

## 十三、oc-collab的服务边界

### 13.1 当前oc-collab的定位

**L1: 单项目协作框架**
- Agent1 + Agent2的工作流
- TODO管理
- 签署流程
- Skill系统
- Git集成
- 部署工具

### 13.2 oc-collab是否应该扩展到多项目？

**两种方案**：

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **方案A** | oc-collab只管单项目 | 简单清晰 | 需要PM-Agent管理多项目 |
| **方案B** | oc-collab扩展到多项目 | 统一架构 | 复杂度增加 |

### 13.3 建议的边界

| 功能 | 归属 | 说明 |
|------|------|------|
| 单项目内协作 | oc-collab | Agent1+2、流程、签署 |
| 项目注册 | PM-Agent | 多项目管理 |
| Agent注册 | PM-Agent | Agent状态监控 |
| 跨项目文档 | PM-Agent | 文档索引 |
| 跨项目评审 | PM-Agent | 评审触发 |

**结论**：oc-collab保持L1定位，PM-Agent作为L3管理多项目。

## 十六、TODO系统设计（跨项目任务传递）

### 16.1 设计原则

TODO系统是**全局共享**的跨项目任务/消息传递系统，不应该被"单项目"限制。

### 16.2 系统架构

```
┌─────────────────────────────────────────┐
│            TODO 系统（全局独立）           │
│  ┌─────────────────────────────────┐   │
│  │     Agent 注册表                    │   │
│  │  agent1@项目A → online           │   │
│  │  agent2@项目A → offline          │   │
│  │  agent1@项目B → online           │   │
│  └─────────────────────────────────┘   │
│  ┌─────────────────────────────────┐   │
│  │     积压队列                      │   │
│  │  agent2@项目A: [TODO-1, TODO-3]  │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
         │
         │ 跨项目路由
         ▼
┌──────────┐   ┌──────────┐   ┌──────────┐
│oc-collab │   │oc-collab │   │oc-collab │
│ 项目A    │   │ 项目B    │   │ 项目C    │
└──────────┘   └──────────┘   └──────────┘
```

### 16.3 Agent注册机制

**启动流程**：
```
Agent启动时：
    │
    ├── 注册到TODO系统
    │   └── 报告：我是谁（ID）、属于哪个项目、状态
    │
    └── 连接TODO服务
```

### 16.4 TODO路由规则

```
Agent1@项目A 发送TODO给 Agent2@项目B：
    │
    ├── TODO系统接收
    ├── 查表：Agent2@项目B 在哪里？
    │   ├── online → 立即推送
    │   └── offline → 存入积压队列
    │
    └── Agent2上线时 → 自动拉取积压TODO
```

### 16.5 核心规则

| 规则 | 说明 |
|------|------|
| **全局共享** | 所有项目共用一个TODO系统 |
| **Agent注册** | Agent启动时自动注册 |
| **在线检测** | 实时感知Agent状态 |
| **路由** | 根据sender-to-receiver规则寻址 |
| **积压** | Agent离线时保存到个人队列 |
| **拉取** | Agent上线后首先处理积压 |

### 16.6 需要开发的功能

| 功能 | 归属 |
|------|------|
| TODO服务（独立进程） | TODO系统 |
| Agent注册机制 | TODO系统 + Agent session |
| sender-to-receiver规则 | TODO系统 |
| 积压队列管理 | TODO系统 |
| Agent上线拉取 | Agent session |

## 十七、PM-Agent定位澄清

### 17.1 PM-Agent的核心定位

**PM-Agent = 整个体系的单点入口**

不是"管理中心"，而是"方便用户自己使用的入口"。

### 17.2 PM-Agent的价值

| 价值 | 说明 |
|------|------|
| **单点入口** | 用户只需要和PM-Agent交互，不用直接操作各个项目 |
| **项目汇总** | 所有项目状态在一个界面可见 |
| **需求统一** | 所有需求通过PM-Agent分发 |
| **进度可见** | 所有项目进度统一视图 |

### 17.3 PM-Agent与TODO系统的关系

```
用户 → PM-Agent → 分发需求
              │
              ├── 项目A oc-collab（Agent1+2处理）
              │
              ├── 项目B oc-collab（Agent1+2处理）
              │
              └── 项目C oc-collab（Agent1+2处理）

PM-Agent分发时通过TODO系统：
    │
    ├── 识别目标Agent
    ├── 路由到对应项目
    └── 积压/推送机制
```

### 17.4 PM-Agent的功能（最终版）

| 功能 | 说明 |
|------|------|
| **单点入口** | 用户统一交互界面 |
| **多项目管理** | 注册所有项目 |
| **Agent注册** | 注册所有Agent |
| **需求分发** | 通过TODO系统分发任务 |
| **进度汇总** | 统一视图 |
| **文档索引** | 跨项目文档入口 |
