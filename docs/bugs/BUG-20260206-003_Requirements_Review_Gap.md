# Bug 报告：需求评审流程断裂

**Bug 编号**: BUG-20260206-003
**严重程度**: P0 (极高)
**发现日期**: 2026-02-06
**发现人**: Agent 1 (产品经理)
**状态**: 待处理

---

## 问题描述

在 v2.2.1 M5 需求评审过程中，发现需求文档与实际执行严重不一致：

| 检查项 | 期望状态 | 实际状态 |
|--------|----------|----------|
| M5 需求文档 | 有独立章节 (2.6) | 只有 1.3 节的 4 行简要提及 |
| M5 需求评审 | Agent 2 已评审 | Agent 2 评审报告未提及 M5 |
| M5 设计创建 | 需求评审后才能创建 | Agent 2 直接创建了设计文档 |
| M5 签署验收 | 需求→设计→代码→签署 | 设计已评审，需求从未被正式评审 |

## 问题表现

### 1. 需求文档结构不完整

**期望**: M5 应该有像 M1-M4 一样的独立章节（2.1, 2.2, 2.3...）

**实际**:
```
1.3 主要变更
6. 双代理认知免疫系统:
   - 困惑信号检测
   - 协作指南 Skill 自动加载
   - 职责边界提醒
   - 动态仓库配置
```

只有 4 行简要列表，没有 FR 开头的详细需求编号。

### 2. Agent 2 需求评审遗漏

**Agent 2 评审报告** (`requirements_v2.2.1_READY_Review_Agent2.md`)：

| 评审项 | 是否提及 |
|--------|----------|
| FR-STATE-001 | ✅ 提及 |
| FR-SIGNOFF-AUTO-001 | ✅ 提及 |
| FR-SIGNOFF-IMPROVE-001 | ✅ 提及 |
| FR-CHANGE-CLARITY-001 | ✅ 提及 |
| FR-ADHOC-001/002/003 | ✅ 提及 |
| FR-CHECKLIST-001 | ✅ 提及 |
| **FR-DUAL-AUTO-001~004 (M5)** | ❌ **未提及** |

Agent 2 评审了 6 个功能模块，但完全遗漏了 M5。

### 3. 流程跳跃

| 时间 | 操作 | 执行人 |
|------|------|--------|
| 2026-02-05 | Agent 2 评审需求文档 | Agent 2 |
| 2026-02-05 | Agent 2 创建 M5 设计文档 | Agent 2 |
| 2026-02-05 | Agent 1 评审 M5 设计文档 | Agent 1 |
| 2026-02-05 | M5 设计通过评审 | Agent 1 + Agent 2 |

**问题**: M5 需求从未被 Agent 2 评审，但设计文档已经被创建并评审通过。

### 4. MEMO vs 正式需求文档冲突

M5 需求存在于：
- `MEMO-2026-02-002_oc-collaboration_Issues_and_Solutions.md` - ✅ 有详细需求
- `MEMO-2026-02-004-ADDENDUM_Dynamic_Checklist.md` - ✅ 有 FR-DUAL-AUTO 验收标准
- `requirements_v2.2.1_DRAFT.md` - ❌ 只有 4 行简要提及
- `requirements_v2.2.1_READY.md` - ❌ 没有独立章节

Agent 不知道应该以哪个文档为准。

## 根本原因分析

| 原因 | 说明 |
|------|------|
| **需求文档结构不完整** | M5 只有 1.3 节的简短列表，没有像 M1-M4 那样有独立章节 |
| **需求完整性检查缺失** | 没有机制确保所有里程碑都有详细需求 |
| **MEMO 与正式需求文档关系不明确** | Agent 不知道 MEMO 中的需求是否需要整合到正式文档 |
| **设计→需求逆向追溯缺失** | 创建设计前没有检查对应需求是否已评审 |
| **评审报告完整性检查缺失** | Agent 2 的评审报告没有自动检查是否覆盖所有需求 |

## 影响范围

| 影响 | 严重程度 |
|------|----------|
| M5 需求从未被正式评审 | P0 |
| M5 设计已通过评审（但需求缺失） | P0 |
| Agent 不知道该以哪个文档为准 | P1 |
| v2.2.1 验收可能不完整 | P1 |

## 建议修复方案

### 方案 1：补充 M5 需求文档

在 `requirements_v2.2.1_DRAFT.md` 中添加 M5 独立章节（第 2.6 节）。

### 方案 2：补充 M5 需求评审

Agent 2 补充评审 M5 需求。

### 方案 3：建立 MEMO 整合流程

1. MEMO 中标识"待整合到正式需求"
2. 超过 7 天未整合的 MEMO 自动提醒
3. 正式需求文档更新时同步 MEMO 状态

### 方案 4：建立完整性检查机制

在 oc-collab 中添加：
- 需求文档完整性检查（所有里程碑都有章节）
- 评审报告完整性检查（覆盖所有需求）
- 设计→需求逆向追溯（创建设计前检查需求评审状态）
