# BUG-20260214-007: TODO编号冲突导致数据损坏

**发现日期**: 2026-02-14  
**发现人**: Agent 1  
**严重度**: P1  
**状态**: OPEN

---

## 问题描述

TODO-357重复创建，导致agent_adhoc_todos.yaml YAML结构损坏。

## 问题原因

| Agent | 创建的TODO | 时间 |
|-------|------------|------|
| Agent1 | TODO-357 | 之前 |
| Agent2 | TODO-357 | 之后 |
| **结果** | **重复** | **冲突** |

## 当前机制

```
├── Agent1可以创建TODO
├── Agent2也可以创建TODO
└── 共用同一编号 → 冲突
```

## 期望行为

**每个Agent维护独立的TODO队列**：

```
Agent1的TODO：TODO-1-001, TODO-1-002, TODO-1-003...
Agent2的TODO：TODO-2-001, TODO-2-002, TODO-2-003...

同时创建也不会冲突！
```

**编号格式**：`TODO-{agent_id}-{sequence}`

| 格式 | 示例 |
|------|------|
| Agent1 | TODO-1-001, TODO-1-002, ... |
| Agent2 | TODO-2-001, TODO-2-002, ... |

## 影响范围

- TODO数据损坏
- YAML解析失败
- 流程断裂

## 根因分析

**没有Agent独立的TODO编号机制**

| 组件 | 实现状态 |
|------|----------|
| Agent1创建TODO | ✅ 支持 |
| Agent2创建TODO | ✅ 支持 |
| 独立编号 | ❌ 缺失 |
| 冲突检测 | ❌ 缺失 |

## 历史

- **此需求可能曾口头讨论，但未找到正式记录**
- **需要在v2.2.10正式提出并实现**

## 临时解决方案

- 手动修复YAML
- 删除重复条目
- 恢复TODO列表

## 根本解决方案

```
v2.2.10 实现：
└── Agent独立TODO编号
        │
        ├── Agent1：TODO-1-001, TODO-1-002...
        ├── Agent2：TODO-2-001, TODO-2-002...
        └── 每个Agent维护自己的计数器
```
