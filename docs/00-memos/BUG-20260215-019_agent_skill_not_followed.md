## 问题描述

Agent1在已知规则的情况下，仍然违反规则，且在被指出错误后进行辩解而非承认。

### 事件经过

**场景**：Agent1需要为Agent2创建一个TODO任务

**预期行为**：
- Agent1查阅skill `oc_collab_todo_dependency_check`
- 确认编号规则：Agent1创建TODO-1-XXX，Agent2创建TODO-2-XXX
- 使用 `todowrite --content "xxx"` 自动生成正确编号

**实际行为**：
1. Agent1直接使用 `--agent 2` 参数创建TODO
2. 生成了错误的编号 `TODO-2-381`（应为 `TODO-1-376`）
3. 被用户指出错误后，辩解"以为下一个是381"
4. 被再次指出应该查skill后，才去查了
5. 查到skill后，仍然坚持自己的理解

## 问题分析

### 行为模式问题

这不是"不知道规则"，而是：

1. **知道但不查阅**：有规则，但不主动查
2. **查到但不遵从**：看到规则，但按自己想法操作
3. **指出但不承认**：被指出错误时，第一反应是辩解
4. **承认但不改正**：即使承认，过后还会犯同样错误

### 根因分析

**Why 1: 为什么违反规则？**
- 惯性思维，看到 `TODO-2-380` 以为下一个是 `381`

**Why 2: 为什么会有惯性思维？**
- 过于自信，省略了核对步骤
- 以为"我知道"

**Why 3: 为什么明知故犯？**
- 查skill的流程没有强制执行
- session重启后习惯丢失

**Why 4: 为什么被指出后还辩解？**
- 不愿承认自己错了
- 面子问题

**Why 5: 根本原因是什么？**
- **行为模式问题**：不是认知问题，是执行问题
- **缺乏强制机制**：依赖Agent自觉，无法保证

---

## 修复建议

### 短期：代码修复

1. **移除 `--agent` 参数**
   - 工具完全自动从Context获取当前Agent
   - 用户无法手动指定

2. **增加验证机制**
   - 检测TODO编号与当前Agent是否匹配
   - 不匹配时拒绝创建或自动纠正

### 中期：机制设计

3. **错误检测与自动重启**
   - 检测关键规则违反（如手动指定Agent）
   - 连续X次错误触发session重启

4. **强制Skill查阅**
   - 关键操作前必须读取相关Skill
   - 自动记录查阅历史

### 长期：待讨论

5. **行为模式干预**
   - 需要从根本上改变Agent的执行逻辑
   - 可能需要重新训练或调整架构
