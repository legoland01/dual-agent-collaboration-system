# Bug报告: Agent1误解了开发TODO的创建规则

**Bug编号**: BUG-20260214-002  
**发现日期**: 2026-02-14  
**发现者**: Agent 1  
**状态**: CLOSED  
**优先级**: P1

---

## 1. Bug描述

### 问题表现

v2.2.9进入开发阶段后，Agent1创建了多个开发TODO。

### 错误认知

Agent1错误地认为：
```
"一个功能一个TODO，创建8个TODO（TODO-340~347）"
"开发完成后立即创建提交TODO（TODO-341）"
"提交完成后立即创建测试TODO（TODO-342）"
```

正确认知：
```
"一个版本一个TODO，只创建1个TODO"
"只创建当前步骤的TODO，不要创建下下步的TODO"
```

---

## 2. 根因分析

### Skill规则

Skill `oc_collab_requirements_guide` 明确规定：

```
| 规则 | 说明 | 示例 |
|------|------|------|
| **只创建当前步骤的TODO** | 只创建"下一步要做"的TODO，不要创建下下步的TODO | ✅ 修复Bug → ❌ 不要同时创建"修复后测试" |
| **一个版本一个TODO** | 一个版本一个开发任务 | v2.2.6 = 1个TODO |

**禁止**：
- ❌ 不要替其他Agent分解任务
- ❌ 不要提前创建下下步的TODO
```

### 历史参考

| 版本 | TODO数量 | 说明 |
|------|----------|------|
| v2.2.6 | 1个 | "实现v2.2.6功能" |
| v2.2.9 | **应该是1个** | "实现v2.2.9全部功能" |

---

## 3. 解决方案

### 已修复

1. ✅ 删除TODO-340~TODO-347（8个功能TODO）
2. ✅ 删除TODO-341（提交TODO）
3. ✅ 删除TODO-342（测试TODO）
4. ✅ 创建TODO-340（1个）："实现v2.2.9全部功能（8个模块）"

### 正确做法

```
当前步骤：
TODO-340: 实现v2.2.9全部功能（8个模块）
          - 8个功能模块
          - 总工时：33h
          - Agent2基于详细设计自行分解

后续步骤（Agent2完成后）：
Agent1自主创建测试TODO（不再提前创建）
```

---

## 4. 教训总结

### 问题分类

| 类型 | 说明 |
|------|------|
| 规则理解 | 违反"只创建当前步骤的TODO" |
| 历史参考 | 应该参考v2.2.6的实践 |
| 过度分解 | 不应该提前分解到下下步 |

### 改进措施

1. **只创建当前步骤的TODO** - 不要创建下下步的TODO
2. **参考历史版本** - v2.2.6是一个版本一个TODO
3. **Agent2完成后再创建下一步** - Agent1自主创建测试TODO
