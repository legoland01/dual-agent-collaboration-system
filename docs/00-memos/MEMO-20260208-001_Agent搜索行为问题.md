## 循环论证问题

### 问题

```
不知道工作目录 → 找不到skill文件
skill文件定义工作目录 → 需要先知道工作目录才能读取
```

### 核心问题

**如何唤起**：即使skill里定义了工作目录，在不知道工作目录的情况下如何"唤起"这个定义？

### 可能的解决方向

| 方向 | 说明 | 可行性 |
|------|------|--------|
| opencode工具自动获取terminal目录 | 工具层面支持 | 需要工具修改 |
| 环境变量 | 设置 `OC_COLLAB_PROJECT_PATH` | 需要用户配置 |
| 默认搜索策略 | Agent默认从当前目录递归查找 | 需要Agent行为改进 |
| 项目标识 | 根目录有特定标识文件（如 `.oc-collab-root`） | 可行 |

---

## 核心问题

**"如何唤起"比"写在哪里"更重要**

---

## 问题描述

### 现象

1. 用户在正确目录打开 terminal 并进入 opencode
2. Agent 执行 `ls -la` 显示默认目录 `/Users/liuzhen/Documents/河广/Product`
3. Agent 看到 Product 目录内容，但没有继续搜索
4. Agent 等用户告知正确工作目录
5. 用户告知路径后，Agent 直接使用完整路径

### 根本原因

| 问题 | 说明 |
|------|------|
| 路径空格 | `/Users/liuzhen/Documents/河广/Product Development/` 含空格 |
| 搜索不充分 | Agent 只看表面，没有主动搜索 |
| 被动等待 | Agent 等用户提供答案，而不是自己找到 |

---

## 以往Agent的做法 vs 这次的做法

| 行为 | 以往Agent | 这次 |
|------|----------|------|
| 目录搜索 | 全力检索，递归查找 | 只看表面 |
| 遇到阻碍 | 继续搜索其他路径 | 等待用户 |
| 路径处理 | 验证路径正确性 | 直接使用 |
| 发现目标 | 找到为止 | 用户告知 |

## 正确做法应该是

```bash
# 步骤1: 检查默认目录
pwd
ls -la

# 步骤2: 如果不是目标，继续搜索
find /Users/liuzhen/Documents/河广/Product -name "*dual-agent*" -type d
ls -la /Users/liuzhen/Documents/河广/Product/oc-collab

# 步骤3: 找到目标后确认
pwd
ls -la

# 步骤4: 切换到正确目录
cd "完整路径"
```

## 路径空格问题

### 问题场景

```
路径: /Users/liuzhen/Documents/河广/Product Development/
                      ↑
                     空格
```

### 错误处理

```bash
# 错误：空格导致路径解析错误
cd /Users/liuzhen/Documents/河广/Product Development/...  ❌

# 正确：使用引号包裹
cd "/Users/liuzhen/Documents/河广/Product Development/..."  ✅
```

## 教训

1. **主动搜索**：不要只看表面，要主动找到目标
2. **验证路径**：使用路径前先确认正确性
3. **处理空格**：路径有空格时必须用引号包裹
4. **不要等待**：用户告知路径后仍需验证
