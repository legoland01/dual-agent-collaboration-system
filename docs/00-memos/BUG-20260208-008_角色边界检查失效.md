## 解决方案

### 方案A: 在所有文件操作前添加检查钩子

```python
# 在Edit/Write工具中添加
def before_edit(filePath):
    checker = RoleBoundaryChecker()
    result = checker.check(current_agent, "edit", filePath)
    if result.result_type == DENIED:
        raise PermissionDeniedError(result.message)

def before_write(filePath):
    checker = RoleBoundaryChecker()
    result = checker.check(current_agent, "edit", filePath)
    if result.result_type == DENIED:
        raise PermissionDeniedError(result.message)
```

### 方案B: Agent1/Agent2工具限制

```python
# 如果检测到Agent1尝试编辑 src/ 或 tests/
# 工具直接拒绝

if agent == "agent1" and filePath.startswith(("src/", "tests/")):
    raise PermissionDeniedError("Agent1无法操作代码文件")
```

### 方案C: 工具箱集成

在OpenCode工具层集成角色检查：

```python
class OpenCodeEditTool:
    def run(self, filePath, oldString, newString):
        # 1. 检查角色权限
        if not can_edit(current_agent, filePath):
            raise PermissionDeniedError(

            )
        # 2. 执行编辑
        ...
```

## 教训

### 为什么role_boundary_checker没有生效？

| 原因 | 说明 |
|------|------|
| 检查只在CLI命令中生效 | `oc-collab compliance check` |
| 工具层未集成检查 | Edit/Write/Bash直接操作文件 |
| Agent未主动使用检查工具 | 没有养成检查习惯 |

### Agent应该怎么做？

1. **编辑文件前**：
   ```bash
   # 检查是否允许
   oc-collab compliance check --role --action edit --target "src/xxx.py"
   ```

2. **如果不确认**：
   ```bash
   # 询问用户
   # "这个文件是src/目录，我能编辑吗？"
   ```

3. **发现需要修改他人代码时**：
   - 创建Bug报告
   - 创建TODO分配给Agent2
   - 不要自己修改
