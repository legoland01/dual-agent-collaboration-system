## 解决方案

### 根本解决方案（需要OpenCode工具层支持）
角色边界检查需要集成到Edit/Write/Bash工具中，这需要修改OpenCode工具本身。

### 当前解决方案（脚本辅助）

#### 创建角色检查脚本
\`\`\`bash
python3 scripts/role_check.py <agent_id> <action> <file_path>
\`\`\`

示例:
\`\`\`bash
# Agent1编辑代码前检查
python3 scripts/role_check.py agent1 edit src/core/signoff.py

# Agent2编辑需求前检查
python3 scripts/role_check.py agent2 edit docs/01-requirements/REQ.md
\`\`\`

#### Agent操作规范

在编辑任何文件前，Agent应该：
1. 运行角色检查脚本
2. 如果返回"denied"，不要编辑该文件
3. 如果需要修改，创建Bug报告分配给有权限的Agent

#### 快速参考

| 场景 | 操作 |
|------|------|
| Agent1想编辑src/ | 先检查：`python3 scripts/role_check.py agent1 edit src/xxx.py` |
| Agent1想编辑tests/ | 先检查：`python3 scripts/role_check.py agent1 edit tests/xxx.py` |
| Agent2想编辑需求 | 先检查：`python3 scripts/role_check.py agent2 edit docs/01-requirements/xxx.md` |
| 检查通过 | 可以继续编辑 |
| 检查拒绝 | 创建Bug报告，不要编辑 |


```python
# 在Edit/Write工具中添加
def before_edit(filePath):
    checker = RoleBoundaryChecker()
    result = checker.check(current_agent, "edit", filePath)
    if result.result_type == DENIED:
        raise PermissionDeniedError(result.message)

def before_write(filePath):
    checker = RoleBoundaryChecker()
    result = checker.check(current_agent, "edit", filePath)
    if result.result_type == DENIED:
        raise PermissionDeniedError(result.message)
```

   ```bash
   # 询问用户
   ```

## 更好的解决方案：文件Owner机制 ⭐

### 核心思路

引入**文件Owner**概念，实现更精确的权限控制：

| 概念 | 说明 |
|------|------|
| 文件Owner | 创建文件的Agent，后续只有Owner能修改 |
| Owner转移 | 通过signoff签署后转移Owner |
| 继承规则 | 签署后文件Owner转移给签署方 |

### 设计原则

```
文件创建者 = Owner
    ↓
签署流程完成
    ↓
Owner转移给签署方（Agent1或Agent2）
    ↓
只有Owner能修改文件
```
