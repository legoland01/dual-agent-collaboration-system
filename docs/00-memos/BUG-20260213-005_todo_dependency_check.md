# BUG-20260213-005: Agent未检查关联TODO状态

**发现日期**: 2026-02-13  
**发现者**: Agent 1  
**状态**: OPEN  
**优先级**: P1

---

## 1. 问题描述

Agent在处理新的TODO时，未先检查关联的前置TODO状态，导致：
- TODO-294（确认需求）未完成时，TODO-295（创建概要设计）已被创建
- 工作流程断裂，可能引发后续问题

---

## 2. 场景还原

```
TODO-294: 确认开放问题Q4澄清并正式通过 v2.2.8 需求文档
          from: agent1 → to: agent2
          status: PENDING

TODO-295: 创建 v2.2.8 概要设计
          from: agent2 → to: agent1
          status: PENDING (2026-02-13T11:25:00 创建)
```

**问题**：TODO-294 未完成，TODO-295 就被创建。

---

## 3. 根因分析

| 因素 | 说明 |
|------|------|
| **流程缺失** | Agent收到TODO时未检查依赖关系 |
| **无提醒机制** | 系统未提示"前置TODO未完成" |
| **习惯问题** | Agent直接处理新TODO，跳过前置检查 |

---

## 4. 影响

| 影响项 | 说明 |
|--------|------|
| **流程断裂** | 需求未确认就进入设计阶段 |
| **返工风险** | 设计可能需根据需求调整 |
| **协作混乱** | Agent2可能等待确认，Agent1已开始设计 |

---

## 5. 解决方案

### 5.1 方案1: Skill流程改进（推荐）

创建Skill规范TODO依赖检查流程：
- 收到TODO时，自动解析`from/to`和`关联文档`
- 检查前置TODO状态
- 若未完成，暂停并提醒

**工时**: 2h | **优先级**: P1

### 5.2 方案2: 工具层校验

在`todowrite`模块添加依赖检查：
- 解析TODO的`from/to`和`requirements_doc`
- 自动验证前置状态
- 状态不匹配时拒绝创建

**工时**: 4h | **优先级**: P2

---

## 6. 决策

| 选项 | 说明 |
|------|------|
| **Skill** | 快速修复，培养习惯 |
| **工具** | 长期方案，但需开发 |

**建议**: 方案1（Skill）+ 口头约定
