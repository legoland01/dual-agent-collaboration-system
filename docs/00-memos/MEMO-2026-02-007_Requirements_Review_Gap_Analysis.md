## 1. 事件描述

在评审 `requirements_v2.2.1.md` 时，未发现 M5 需求章节缺失，直接导致：

1. 基于不完整需求创建设计文档
2. 设计评审通过，但基础需求不完整
3. 事后才由 Agent 1 发现问题

**严重程度**: P0（流程漏洞，影响整个版本基础）

---

## 2. 5-Why 根因分析

### Why 1: 为什么 M5 需求缺失没有被发现？

**答案**: 评审时没有执行"需求完整性检查"

---

### Why 2: 为什么没有执行需求完整性检查？

**答案**: 评审流程中没有这个检查点

**追问**: 为什么评审流程中没有这个检查点？

---

### Why 3: 为什么评审流程中没有需求完整性检查？

**答案**: 协作指南 v1 没有要求

**追问**: 为什么协作指南 v1 没有这个要求？

---

### Why 4: 为什么协作指南 v1 没有需求完整性检查？

**答案**: 之前没有发生过类似问题，没有经验

**追问**: 为什么之前没有发生？

---

### Why 5 (深层根因): 为什么之前没有发生？

| 版本 | 规模 | 发现难度 |
|------|------|----------|
| v2.0.0 | 小（1-2 个里程碑） | 容易检查 |
| v2.1.0 | 中（3 个里程碑） | 较容易检查 |
| v2.2.1 | 大（5 个里程碑） | 容易遗漏 |

**深层根因**: 之前版本规模小，需求文档短，完整性检查是"显性"的；v2.2.1 规模变大后，完整性检查变成"隐性"需求，但流程没有跟上。

---

## 3. 根本原因总结

```
规模变大 → 人工检查难度增加 → 需要系统性检查机制
              ↓
          没有系统性机制 → 依赖人工自觉 → 容易遗漏
```

**核心问题**: 依赖人工自觉检查流程漏洞，缺少自动化或强制性的检查机制。

### 4.3 长期方案（功能需求）

#### FR-AUTO-001: 需求完整性自动检查

**描述**: 在创建设计文档前，自动检查需求文档是否完整。

**触发条件**: `oc-collab design create` 或 `oc-collab phase advance`

**检查项**:
- 所有计划的里程碑（M1~M5）都有对应章节
- 每个章节有实质性内容（非空）
- 无遗留 MEMO 未整合

**命令示例**:
```bash
oc-collab design create --project test
# 输出:
# === 需求完整性检查 ===
# ⏳ M1 Agent Manager: 存在
# ⏳ M2 Project Manager: 存在
# ⏳ M3 Meeting Manager: 存在
# ⏳ M4 Story Manager: 存在
# ❌ M5 E2E Tests: 缺失
# ⚠️ 检查未通过：M5 需求缺失
# 建议: 请先补充 M5 需求章节
```

#### FR-AUTO-002: 阶段推进门槛检查

**描述**: 在推进阶段前，自动检查前置条件是否满足。

**前置条件检查**:
| 当前阶段 | 推进条件 |
|----------|----------|
| requirements_draft | 需求文档完整、格式正确 |
| requirements_review | 双方已完成评审 |
| design_review | 对应需求已签署 |
| development | 设计已签署、单元测试通过 |

**命令示例**:
```bash
oc-collab phase advance
# 输出:
# === 阶段推进检查 ===
# ❌ 检查未通过
# - 需求不完整：M5 章节缺失
# - 请补充需求后再试
```

#### FR-AUTO-003: 需求文档版本追踪

**描述**: 在 `state/project_state.yaml` 中记录每个里程碑的完整性状态。

**存储格式**:
```yaml
milestones:
  m1:
    status: "approved"  # draft / in_review / approved
    complete: true
    sections_count: 5
  m2:
    status: "approved"
    complete: true
    sections_count: 8
  m3:
    status: "approved"
    complete: true
    sections_count: 6
  m4:
    status: "approved"
    complete: true
    sections_count: 7
  m5:
    status: "draft"
    complete: false  # ❌ 缺失
    sections_count: 0
```

**检查命令**:
```bash
oc-collab requirements status
# 输出:
# === 需求完整性状态 ===
# M1: ✅ 完整 (5 sections) - approved
# M2: ✅ 完整 (8 sections) - approved
# M3: ✅ 完整 (6 sections) - approved
# M4: ✅ 完整 (7 sections) - approved
# M5: ❌ 缺失 (0 sections) - draft
```
