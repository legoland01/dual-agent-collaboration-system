## 1. 背景

在日常协作过程中，发现 oc-collab 框架在"资深项目"（oc-collab 自身）和"Financial 项目"（业务系统）中的表现存在明显差异，引发了对 oc-collab 核心价值和适用场景的深入讨论。

---

## 2. 核心发现

### 2.1 oc-collab 在不同项目中的表现差异

| 项目 | 使用 oc-collab 的方式 | 结果 |
|------|----------------------|------|
| **oc-collab 自身** | 原生使用，严格遵循 | 顺畅，里程碑清晰 |
| **Financial 项目** | 混合使用，跳过签署 | 磕磕绊绊，同样的问题重复发生 |

### 2.2 对比分析

| 维度 | oc-collab 资深项目 | Financial 项目 |
|------|-------------------|----------------|
| **项目类型** | oc-collab 框架自身 | 业务系统（PDF生成） |
| **使用方式** | 原生使用 | 移植/混合使用 |
| **状态管理** | 完整的 state 文件 | 几乎没有 state |
| **里程碑签署** | 严格遵循 | 几乎跳过 |
| **测试覆盖** | 单元测试+E2E+黑盒 | 很少测试 |
| **问题追踪** | memo 记录 | 反复踩坑 |

### 2.3 根本原因

**Financial 项目没有真正使用 oc-collab**：

| 应该做的 | Financial 项目的实际情况 |
|---------|-------------------------|
| `oc-collab init` 初始化 | ❌ 直接开始写代码 |
| `project_state.yaml` 状态 | ❌ 没有状态文件 |
| 里程碑签署 | ❌ 没有签署 |
| 黑盒测试 | ❌ 没有执行 |
| 问题追踪 | ❌ 同样的问题重复发生 |

---

## 3. 问题本质

### 3.1 核心问题

```
不是"如何适配 Financial 项目"
而是"oc-collab 的核心机制如何在任何项目中都发挥作用"
```

### 3.2 oc-collab 的核心价值（与项目无关）

| 核心价值 | 说明 | 适用任何项目 |
|----------|------|-------------|
| **双代理协作** | 产品 + 开发，互相监督 | ✅ |
| **里程碑签署** | 质量门禁，不跳过 | ✅ |
| **状态管理** | 单一事实来源 | ✅ |
| **问题追踪** | 不重复踩坑 | ✅ |
| **记忆机制** | 记得教训 | ✅ |

### 3.3 真正的挑战

```
oc-collab 应该像"文化"而不是"框架"

文化：双代理协作、签署、质量门禁、记忆
框架：具体的文件结构、命令、流程

文化可以渗透到任何项目
框架需要适应项目特点
```

---

## 4. 讨论的解决方案

### 4.1 双代理认知免疫系统（已加入 v2.2.1）

**问题背景**：Agent 在协作过程中会"忘记"另一个 Agent 的存在，导致独自决策、跳过评审等问题。

**解决方案**：通过 Skill 机制，在 Agent 困惑时自动加载协作指南。

| FR 编号 | 功能 | 来源 |
|---------|------|------|
| FR-DUAL-AUTO-001 | Skill 自动加载机制 | 协作困惑 |
| FR-DUAL-AUTO-002 | 困惑信号检测 | 协作困惑 |
| FR-DUAL-AUTO-003 | 协作指南 Skill 内容（含动态仓库配置） | 协作困惑 |
| FR-DUAL-AUTO-004 | 职责边界提醒 | 协作困惑 |

**核心功能**：
- Agent 困惑时自动加载协作指南
- 检测角色混淆、不知道下一步、独自决策等信号
- 提供动态仓库配置（从 .git/config 读取）

### 4.2 新项目启动方案

**最小化启动** = 只需要几样东西就能运转

| 最小组件 | 说明 |
|----------|------|
| `oc-collab init` | 初始化项目结构 |
| `project_state.yaml` | 状态文件 |
| 2 个 Agent | 产品 + 开发 |
| 第一个里程碑 | 从需求开始 |

**不依赖项目类型**：
- PDF 生成项目 ✅
- Web 应用 ✅
- API 服务 ✅
- 任何软件项目 ✅

### 4.3 Skill 与新项目启动的结合

**oc_collab_collaboration_guide Skill 结构**：

```
基础篇
├── 双代理是什么
```

## 9. 结论

### 9.1 核心思路

- oc-collab 的核心价值（双代理、签署、状态、记忆）可以适用于任何项目
- 通过 Skill 机制解决"搞不清"的问题
- 新项目启动只需要最小组件，然后渐进式引入

### 9.2 关键洞察

```
不是"适配项目特点"
而是"如何让 oc-collab 足够轻量，易于采用"
```

### 9.3 核心原则

1. **最小化启动**：新项目只需要最小组件
2. **渐进式引入**：逐步完善 oc-collab 机制
3. **Skill 驱动**：通过 Skill 解决协作困惑
4. **跨项目适用**：核心价值不依赖项目类型
