## 问题描述

v2.3.1 验收测试发现以下严重问题：

### BUG-001: CLI使用旧的ComplianceEnforcer阻止Agent1创建TODO

**问题**: CLI (enhanced_commands.py) 仍使用 v2.2.9 的 `ComplianceEnforcer`，阻止 Agent1 执行所有 todowrite 命令。

**预期行为**: 
- 根据 v2.3.1 详细设计，Agent1 应该可以创建 TODO-1to2-xxx 格式的TODO
- 合规检查应该阻止非法格式 (如 TODO-2to3-xxx)

**实际行为**:
```
$ oc-collab todowrite --content "测试" --to agent2
⛔ Agent1禁止执行todowrite命令。
```

**根因**: 
- src/cli/enhanced_commands.py 第100行导入的是 `ComplianceEnforcer`
- 应该是 v2.3.1 的 `ComplianceChecker`

---

### BUG-002: TODO持久化失败 - 新TODO未正确创建

**问题**: 执行 todowrite 后，新TODO未被创建为独立条目，而是被嵌入到现有TODO的content中。

**复现步骤**:
1. 执行 `oc-collab todowrite --content "测试" --to 1`
2. 输出显示 "✅ 待办已创建: [TODO-2to1-006]"
3. 执行 `oc-collab todo list` 显示 "TODO列表为空"
4. 检查 YAML 文件发现 TODO-2to1-006 出现在其他TODO的content字段中

**预期**: 新TODO应该作为独立条目添加到 agent_adhoc_todos.yaml

**实际**: TODO被错误地嵌入到现有TODO的content中

---

## 修复建议

### 修复BUG-001:
1. 修改 src/cli/enhanced_commands.py
2. 将 `from ..core.compliance_enforcer import ComplianceEnforcer` 改为 `from ..core.compliance_checker import ComplianceChecker`
3. 更新 todowrite 命令的合规检查逻辑，使用新的 ComplianceChecker

### 修复BUG-002:
1. 检查 todo_sync_manager.py 的 add_todo 方法
2. 确保新TODO被正确添加为独立的 YAML 条目
3. 验证 YAML 结构正确性
