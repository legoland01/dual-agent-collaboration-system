## 一、Agent身份体系（Proposal_2026-02-026）

### 1.1 核心方案（已确认）

| 内容 | 决定 |
|------|------|
| Agent ID | 昵称（如zhangsan），不是真名 |
| 编号 | 产品经理=1，架构师=2，其他=3,4... |
| 项目内称呼 | 用职务（产品经理/架构师），系统自动映射到ID |
| 多项目兼任 | 不允许（重启terminal解决） |
| 角色扩展 | 支持（可添加测试工程师等） |
| Skill | 按职责编写，不按岗位 |
| 存储 | SQLite（Agent注册表+项目配置） |

### 1.2 实施安排

- **v2.3.1**: 保持现有术语（Agent1/Agent2），暂不引入产品经理/架构师
- **v2.4+**: 引入新术语 + SQLite

## 四、通知机制讨论

### 4.1 现状

| 组件 | 状态 |
|------|------|
| StateNotifier | ✅ 已有 |
| StateReceiver | ✅ 已有（Flask服务） |
| 自动启动 | ❌ 缺失 |

### 4.2 问题

- Agent2需要手动启动StateReceiver
- 人手动通知不过来

### 4.3 讨论结论

- **拉模式**：Agent2手动`todo list`查看 - 不够自动化
- **推模式**：TODO创建后自动推给Agent2 - 需要机制
- **Webhook已有**：需要让notification机制运转起来

### 4.4 待选择方案

| 方案 | 描述 |
|------|------|
| A | 定时轮询：Agent2定时检查"分配给我的TODO" |
| B | 常驻服务：Agent2始终运行StateReceiver |
| C | 外部通知：推送到邮件/钉钉/飞书 |
