## 一、背景

### 1.1 需求背景

用户（项目经理）目前面临的问题：
- 正在执行很多项目，绝大多数是人在使用其他编码工具
- 需要管理：客户需求、开发进度、现有问题、问题解决情况、代码更新情况
- 希望逐步引入oc-collab管理项目的开发
- 最终让Agent直接接手项目开发

### 1.2 核心痛点

| 痛点 | 说明 |
|------|------|
| 信息分散 | 需求来自微信、邮件、聊天等各种渠道 |
| 手动维护 | 项目文档、问题跟踪、进度报告需要手动更新 |
| 进度不明 | 难以快速了解各项目的实际进度 |
| 工具割裂 | 项目管理工具用起来太麻烦 |

### 1.3 解决方案

**构建一个项目管理Agent (PM-Agent)**：
- 所有信息丢给Agent，Agent自动分类和处理
- 自动从Git读取进度，更新项目状态
- 自动维护项目文档和进度报告

## 三、核心功能设计

### 3.1 PM-Agent能力

| 能力 | 输入 | 处理 | 输出 |
|------|------|------|------|
| **信息接入** | 任意文本（微信/邮件/聊天/文档） | 意图识别、实体提取 | 结构化信息 |
| **项目识别** | 任意信息 | 关键词匹配/语义分析 | 归属项目ID |
| **类型分类** | 信息内容 | 意图识别 | 需求/BUG/会议/进度/其他 |
| **文档生成** | 结构化信息 | 模板填充 | 需求文档/BUG报告/会议纪要 |
| **Git分析** | git log | 提交统计 | 进度更新、变更记录 |
| **进度报告** | 项目数据 | 聚合分析 | 项目进度报告 |

### 3.2 信息处理流程

```
输入信息
    │
    ▼
┌──────────────────┐
│  1. 项目识别       │ ← 匹配项目关键词
│     (属于哪个项目) │
└──────────────────┘
    │
    ▼
┌──────────────────┐
│  2. 类型分类       │ ← 识别是需求还是BUG
│     (需求/BUG/其他)│
└──────────────────┘
    │
    ▼
┌──────────────────┐
│  3. 实体提取       │ ← 提取关键信息
│  (谁/什么/何时)   │
└──────────────────┘
    │
    ▼
┌──────────────────┐
│  4. 文档生成       │ ← 生成对应文档
│  (按模板填充)     │
└──────────────────┘
    │
    ▼
┌──────────────────┐
│  5. 状态更新       │ ← 更新项目状态
│  (项目进度/问题)   │
└──────────────────┘
```

### 3.3 Git进度同步

| 功能 | 说明 |
|------|------|
| **自动拉取** | 定时从Git拉取最新提交 |
| **提交统计** | 统计各项目的提交数量、频率 |
| **变更提取** | 从commit message提取变更类型 |
| **进度更新** | 根据代码提交更新项目进度 |
| **问题关联** | 关联commit和对应的需求/BUG |

### 5.2 技术选型

| 组件 | 推荐方案 | 说明 |
|------|----------|------|
| 前端 | Vue.js | 轻量、易上手 |
| 后端 | FastAPI | Python，与oc-collab统一 |
| 数据库 | SQLite (轻量) / PostgreSQL | 项目数据存储 |
| Git | GitPython | 读取Git仓库 |
| 部署 | Docker | 便于分发 |

### 5.3 数据模型

```python
# 项目
class Project:
    id: str
    name: str
    description: str
    status: str  # planning / developing / testing / online
    progress: int  # 0-100
    oc_collab_enabled: bool
    created_at: datetime
    updated_at: datetime

# 需求
class Requirement:
    id: str
    project_id: str
    title: str
    description: str
    status: str  # pending / in_progress / completed
    source: str  # email / chat / meeting / manual
    created_at: datetime

# BUG
class Bug:
    id: str
    project_id: str
    title: str
    description: str
    severity: str  # P0 / P1 / P2
    status: str  # pending / in_progress / resolved
    related_commits: list[str]
    created_at: datetime

# Git活动
class GitActivity:
    project_id: str
    commit_hash: str
    message: str
    author: str
    timestamp: datetime
```

## 六、与oc-collab的整合

### 6.1 整合方式

| 方向 | 说明 |
|------|------|
| **单向** | PM-Agent → oc-collab：生成需求后转成oc-collab TODO |
| **双向** | 状态同步：进度、问题双向同步 |

### 6.2 整合功能

| 功能 | 说明 |
|------|------|
| **需求导入** | PM-Agent识别到需求后，可申请导入oc-collab |
| **进度同步** | oc-collab项目进度回写到PM-Agent |
| **状态联动** | oc-collab TODO状态变化同步到PM-Agent |

## 九、风险与应对

| 风险 | 应对 |
|------|------|
| 意图识别不准 | 提供人工确认机制，积累数据优化 |
