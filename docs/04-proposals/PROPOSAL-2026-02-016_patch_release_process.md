## 二、Patch定义

### 2.1 Patch版本说明

```
格式: v{Major}.{Minor}.{Patch}.{Fix}

示例:
- v2.2.12  →  v2.2.12.1 (第一个patch)
- v2.2.12.1 → v2.2.12.2 (第二个patch)
```

### 2.2 Patch vs Minor vs Major

| 版本类型 | 触发条件 | 示例 |
|----------|----------|------|
| **Patch** | Bug修复，不增加功能 | v2.2.12 → v2.2.12.1 |
| **Minor** | 新功能，向后兼容 | v2.2.12 → v2.2.13 |
| **Major** | 不兼容变更 | v2.2.x → v3.0.0 |

---

## 三、Patch发布条件

### 3.1 触发条件

| 条件 | 说明 | 是否发布Patch |
|------|------|--------------|
| 影响日常开发 | 阻塞Agent协作 | ✅ 是 |
| 阻塞工作流程 | 无法正常完成TODO | ✅ 是 |
| YAML/数据损坏 | 导致数据丢失或错误 | ✅ 是 |
| 安全漏洞 | 需要立即修复 | ✅ 是 |
| 功能增强 | 新功能需求 | ❌ 否 (Minor) |
| 体验优化 | 非阻塞性问题 | ❌ 否 (下个版本) |

### 3.2 Patch优先级

| 优先级 | 条件 | 响应时间 |
|--------|------|----------|
| **P0** | 阻塞开发 | 立即修复，24h内发布 |
| **P1** | 影响效率 | 24-48h内发布 |
| **P2** | 小问题 | 下个版本修复 |

## 四、Patch发布流程

### 4.1 流程图

```
发现Bug
    │
    ▼
┌─────────────────────┐
│ 判断是否需要Patch？  │ ← 参照3.1发布条件
└─────────┬───────────┘
          │
    ┌─────┴─────┐
    ▼           ▼
   是           否
    │           │
    ▼           ▼
创建Bug报告   记录到下个版本
    │
    ▼
┌─────────────────────┐
│ 创建Patch TODO      │
└─────────┬───────────┘
          │
          ▼
    ┌─────┴─────┐
    ▼           ▼
   自动         手动
    │           │
    ▼           ▼
 TODO-1-xxx   Agent1创建
    │
    ▼
┌─────────────────────┐
│ 修复Bug             │
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ Patch验收           │ ← 4.2验收标准
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 发布Patch           │ ← 4.3发布步骤
└─────────┬───────────┘
          │
          ▼
更新版本号 → 构建 → PyPI → 验证 → 完成
```

### 4.2 Patch验收标准

| 验收项 | 标准 | 检查方式 |
|--------|------|----------|
| Bug已修复 | 原问题不再存在 | 手动验证 |
| 无回归 | 现有功能正常 | 单元测试 |
| 代码质量 | 无严重警告 | pytest/ruff |
| 文档更新 | CHANGELOG已更新 | grep验证 |

### 4.3 Patch发布步骤

```bash
# 1. 更新版本号
# pyproject.toml: version = "2.2.12.1"

# 2. 更新CHANGELOG.md
## v2.2.12.1 (2026-02-15)
### Fixed
- BUG-20260215-001: TODO编号生成逻辑
- BUG-20260215-002: AutoBugDetector未工作

# 3. 构建包
python -m build

# 4. PyPI上传
twine upload dist/*

# 5. Git提交
git add pyproject.toml CHANGELOG.md
git commit -m "fix: patch v2.2.12.1 - 修复TODO编号和AutoBugDetector"
git tag v2.2.12.1
git push && git push origin v2.2.12.1

# 6. 验证
curl https://pypi.org/pypi/opencode-collaboration/2.2.12.1/json
```

## 五、版本号管理规则

### 5.1 版本号格式

```toml
# pyproject.toml
[project]
version = "2.2.12.1"  # Major.Minor.Patch.Fix
```

### 5.2 版本号自增规则

| 操作 | 自增方式 |
|------|----------|
| 修复第一个Bug | 2.2.12 → 2.2.12.1 |
| 修复第二个Bug（同一版本） | 2.2.12.1 → 2.2.12.2 |
| 新功能 | 2.2.12 → 2.2.13 |
| 不兼容变更 | 2.2.x → 3.0.0 |
