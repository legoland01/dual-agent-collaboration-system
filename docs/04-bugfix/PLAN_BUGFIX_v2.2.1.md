## 修复方案

### 1. BUG-20260205-001: Agent 流程合规性不足

**问题**: Agent 反复需要人类提醒才能回到 oc-collab 规范流程

**相关文档**: `docs/bugs/BUG-20260205-001.md`

**修复内容**:
在 `docs/COLLABORATION_GUIDE.md` 中增加"流程合规检查"章节：
- Agent 启动时的自我检查清单
- 关键决策点的合规检查点
- 违反流程规范的提醒机制

**验收标准**:
| 标准 | 验证方式 |
|------|----------|
| 协作指南中有完整的流程合规检查清单 | 代码审查 |
| Agent 启动时能查看合规检查要点 | 文档审查 |

**工时**: 2h

---

### 2. BUG-20260205-002: Agent 2 主动越界问题

**问题**: Agent 2 在没有收到正式任务指派的情况下，主动开始实现功能

**相关文档**: `docs/bugs/BUG-20260205-002.md`

**修复内容**:
在 `docs/COLLABORATION_GUIDE.md` 中明确"任务触发"流程：
- Agent 2 的职责边界：等待 Agent 1 发布任务后才能开始开发
- 任务检查点：开发前必须确认有正式任务
- 违规提醒：发现越界行为时的自动提示

**验收标准**:
| 标准 | 验证方式 |
|------|----------|
| 协作指南中有明确的任务触发流程 | 代码审查 |
| Agent 2 开发前会检查是否有待处理任务 | 文档审查 |

**工时**: 2h

---

### 3. BUG-20260206-003: 需求评审流程断裂

**问题**: M5 需求从未被正式评审，但设计已被创建并通过评审

**相关文档**: `docs/bugs/BUG-20260206-003.md`

**修复内容**:
在 `docs/COLLABORATION_GUIDE.md` 中增加以下检查清单：

| 检查项 | 说明 |
|--------|------|
| 需求完整性检查 | 创建设计前检查需求文档是否完整（所有里程碑必须有章节） |
| 设计前检查 | 创建设计前检查对应需求是否已评审 |
| MEMO 处理流程 | MEMO 中的需求需要整合到正式需求文档后才能使用 |

**验收标准**:
| 标准 | 验证方式 |
|------|----------|
| 协作指南中有完整的需求完整性检查清单 | 代码审查 |
| 协作指南中有明确的设计前检查流程 | 代码审查 |
| 协作指南中有 MEMO 处理流程说明 | 代码审查 |

**工时**: 3h
