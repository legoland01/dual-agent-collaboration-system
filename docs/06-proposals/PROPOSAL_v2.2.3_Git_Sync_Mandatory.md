## 1. 问题定义

### 1.1 症状

| 场景 | 表现 | 影响 |
|------|------|------|
| 文件修改后 | git sync 依赖人工操作 | 容易遗忘 |
| session 重启 | Agent 承诺不可延续 | 协作上下文丢失 |
| 多人协作 | 各自为政 | 版本混乱 |

### 1.2 根因

```
问题: "修改即同步" 不是系统强制行为
原因:
├── 工具层面: 没有强制同步命令
├── 流程层面: 没有制度性约束
└── 文化层面: 依赖个人习惯
```

### 1.3 用户痛点

> "我需要体制性的保障，而不是你的承诺。你的承诺在 compaction 或 session 重启之后将是一张废纸。"

---

## 2. 解决方案

### 2.1 方案 A: 集成到现有命令

**描述**: 修改现有命令，自动触发 git sync。

| 命令 | 行为变化 |
|------|----------|
| `oc-collab phase-advance` | 自动 git add → commit → push |
| `oc-collab todo done` | 自动 git add → commit |
| `oc-collab signoff` | 自动 git add → commit → push |

### 2.2 方案 B: 新增强制命令

**描述**: 新增专用同步命令。

```bash
# 同步当前状态
oc-collab git sync

# 同步并显示状态
oc-collab git sync --status

# 强制同步（跳过确认）
oc-collab git sync --force
```

### 2.3 方案 C: 自动触发 + 强制提醒

**描述**: 在关键节点自动提醒，必要时强制同步。

| 触发条件 | 行为 |
|----------|------|
| 文件修改未同步 | 显示警告 |
| session 结束前 | 强制确认 |
| 多人协作冲突 | 阻止继续操作 |

---

## 3. 推荐方案

**推荐**: 方案 A + 方案 B 结合

理由：
- 集成到现有命令降低使用成本
- 新增专用命令提供灵活性
- 自动 + 手动 双保险
