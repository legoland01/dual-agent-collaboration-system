## 角色定位

| 角色 | 职责 | 禁止 |
|------|------|------|
| **Agent 1** | 创建概要设计、签署"创建" | 代码实现、技术选型 |
| **Agent 2** | 评审概要设计 | 创建概要设计 |

---

## 概要设计 vs 详细设计

| 维度 | 概要设计 | 详细设计 |
|------|----------|----------|
| 视角 | 用户/功能 | 技术/代码 |
| 抽象级别 | 高（What） | 低（How） |
| 责任人 | Agent 1 | Agent 2 |
| 关注点 | 功能模块、分组、关系 | 技术模块、代码实现 |
| 与产品关系 | 直接对应 | 间接映射 |

## 核心原则

### 1. 功能模块抽象

**原则**：从用户视角出发，系统提供什么能力

```
用户视角：
- 用户能做什么？
- 系统显示什么？
- 数据如何流转？

非用户视角（详细设计）：
- 用什么技术实现？
- 代码结构是什么？
- 算法细节是什么？
```

### 2. 功能分组

将相关功能组织在一起，形成清晰的功能树：

```
系统功能
├── 用户管理
│   ├── 用户注册
│   ├── 用户登录
│   └── 权限管理
├── 需求管理
│   ├── 需求创建
│   ├── 需求评审
│   └── 需求跟踪
└── 协作管理
    ├── 任务分配
    ├── 进度跟踪
    └── 签署确认
```

### 3. 功能关系定义

| 关系类型 | 说明 | 示例 |
|----------|------|------|
| **调用关系** | 功能A调用功能B | 需求评审 → 签署确认 |
| **数据依赖** | 功能A需要功能B的数据 | 任务分配 → 用户管理 |
| **时序关系** | 功能A完成后才能做功能B | 需求创建 → 需求评审 |
| **互斥关系** | 功能A和功能B不能同时用 | - |

### 4. 与产品路线图对齐

概要设计必须回答：
- 这个功能在产品路线图中的位置？
- 这个功能解决了用户的什么问题？
- 这个功能与前后版本的关系？

## 标准文档结构

### 必须章节

| 章节 | 是否必须 | 说明 |
|------|---------|------|
| 1. 功能模块概览 | ✅ | 系统提供哪些功能组 |
| 2. 功能模块关系 | ✅ | 功能之间的调用/依赖/数据流 |
| 3. 产品路线图定位 | ✅ | 本版本在路线图中的位置 |
| 4. 用户故事/场景 | ✅ | 功能对应的用户使用场景 |
| 5. 外部接口定义 | ✅ | 与外部系统的交互点 |
| 6. 约束与假设 | ✅ | 产品的约束条件 |
| 7. 签署确认 | ✅ | 双人签署 |

### 可选章节

| 章节 | 说明 |
|------|------|
| 数据流图 | 功能之间的数据流转 |
| 状态机 | 功能状态转换 |
| 风险点 | 潜在的产品风险 |
