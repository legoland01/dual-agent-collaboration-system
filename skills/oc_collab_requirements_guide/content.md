# OC-Collab 需求编写指南

## 快速开始

### 创建新需求文档

```bash
# 1. 复制模板
cp docs/01-requirements/TEMPLATE_requirements.md docs/01-requirements/requirements_vX.X.X_DRAFT.md

# 2. 编辑文档
#    - 填写所有必须字段
#    - 明确验收标准
#    - 预估工时

# 3. 状态流转
#    DRAFT → READY (产品完成) → APPROVED (开发确认)
```

### 发布前检查

```bash
./scripts/check_requirements.sh docs/01-requirements/requirements_vX.X.X_READY.md
```

## 标准文档结构

### 必须章节

| 章节 | 是否必须 | 说明 |
|------|---------|------|
| 1. 概述 | ✅ 必须 | 版本信息、核心原则 |
| 2. 功能需求 | ✅ 必须 | 每个功能需有验收标准 |
| 3. CLI 命令清单 | ✅ 必须 | 新增/变更命令 |
| 4. 工时预估 | ✅ 必须 | 按时交付 |
| 5. 依赖关系 | ✅ 必须 | 明确依赖链 |
| 6. 签署确认 | ✅ 必须 | 双人签署 |

### 验收标准格式

```markdown
**验收标准**:
- [ ] 标准 1
- [ ] 标准 2
```

### CLI 命令清单格式

```markdown
### 新增命令

| 命令 | 说明 | 工时 |
|------|------|------|
| `oc-collab xxx` | 说明 | Xh |
```

## 双签流程

### 签署顺序

| 步骤 | 签署人 | 说明 |
|------|--------|------|
| 1 | Agent 1 | 产品负责人创建并签署 |
| 2 | Agent 2 | 开发负责人评审并签署 |

### 签署状态

| 状态 | 说明 |
|------|------|
| DRAFT | 草稿（产品编写中） |
| READY | 就绪（待开发评审） |
| APPROVED | 批准（可开始开发） |

## 推迟功能处理

如果本版本有推迟功能：

1. 创建 `PARKED_vX.X.X_features.md`
2. 记录：
   - 功能名称和来源
   - 推迟原因
   - 原始验收标准
   - 后续建议版本
   - 相关文档路径

## 常见问题

### Q: 验收标准要写多少项？

A: 每个功能至少 3-5 项验收标准，覆盖正常流程和异常流程。

### Q: 工时预估不准怎么办？

A: 
- 首次实现：按估算工时的 1.5-2 倍计算
- 复用的功能：按估算的 0.5-0.75 倍计算
- 复杂功能：拆分为多个小版本

### Q: 漏了章节怎么办？

A: 运行检查脚本 `./scripts/check_requirements.sh`，会自动检测缺失章节。
