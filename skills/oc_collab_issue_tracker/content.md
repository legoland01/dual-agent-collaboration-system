# oc-collab 问题追踪系统

## 一、核心原则

### 1.1 为什么要追踪问题

- **避免重复发现问题**: 同样的问题被反复发现、反复修复
- **追溯根因**: 问题背后的设计缺陷、流程漏洞
- **沉淀经验**: 每次问题都是改进系统的机会
- **责任明确**: 问题有负责人、有记录、可追溯

### 1.2 问题生命周期

```
发现 → 记录 → 分析 → 修复 → 验证 → 关闭
```

每个阶段必须有记录，不能"口头传递"。

## 二、问题分类

### 2.1 ID前缀规范

| 前缀 | 类型 | 说明 | 示例 |
|------|------|------|------|
| BUG | 代码缺陷 | 程序错误、功能缺失 | BUG-20260210-001 |
| TODO | 待开发任务 | 新功能、优化任务 | TODO-20260210-002 |
| RFC | 设计评审请求 | 需要评审的设计变更 | RFC-20260210-003 |
| TEST | 测试任务 | 测试用例、验证任务 | TEST-20260210-001 |
| DOC | 文档任务 | 文档改进 | DOC-20260210-001 |
| PROPOSAL | 提案 | 新功能提案 | PROPOSAL-2026-02-001 |
| MEMO | 备忘录 | 会议记录、临时记录 | MEMO-2026-02-010 |

### 2.2 优先级

| 级别 | 说明 | 响应时间 |
|------|------|----------|
| P0 | 阻塞 - 系统不可用 | 立即修复 |
| P1 | 高 - 功能严重受损 | 24小时内 |
| P2 | 中 - 功能有缺陷 | 本周内 |
| P3 | 低 - 改进建议 | 排期 |

### 2.3 状态流转

```
OPEN → IN_PROGRESS → COMPLETED
                ↓
            REOPEN（如果复发）
```

## 五、工作流程

### 5.1 发现问题

**谁可以发现问题**:
- Agent1: 测试、设计评审、代码审查
- Agent2: 开发、自测、代码审查

**发现后的动作**:
1. 确认问题可复现
2. 准备复现步骤
3. 评估严重程度

### 5.2 记录问题

**Agent1的职责**:
1. 创建问题文件 `docs/00-memos/BUG-YYYYMMDD-XXX_描述.md`
2. 填写问题模板所有字段
3. 更新 `state/ISSUE_INDEX.md`
4. 创建TODO任务指派给Agent2
5. 编写测试用例（如果适用）

**禁止**:
- ❌ 口头告知Agent2
- ❌ 只说不记录
- ❌ 模糊描述

### 5.3 修复问题

**Agent2的职责**:
1. 阅读问题文件，理解问题
2. 分析根因
3. 提出解决方案
4. 执行修复
5. 在问题文件中记录修复情况
6. 更新 ISSUE_INDEX

**禁止**:
- ❌ 不看问题文件直接修复
- ❌ 修复后不更新问题记录

### 5.4 验证问题

**验证方式**:
1. 运行测试用例
2. 手动验证
3. 对比修复前后

**验证后**:
1. 更新问题文件验证结果
2. 将问题状态改为 COMPLETED
3. 在 ISSUE_INDEX 中移至"已关闭问题"

## 六、与TODO的区别

| 维度 | 问题(BUG) | 任务(TODO) |
|------|----------|-----------|
| 来源 | 测试发现、用户反馈 | 产品规划 |
| 性质 | 修复缺陷 | 新功能/优化 |
| 模板 | BUG模板 | state/todos.db (SQLite) |
| 触发 | bug_found, test_failure | new_requirement |

**重要**: 修复BUG时，如果有优化建议，应该创建新的TODO，而不是混在一起。

## 七、快速参考

### 查看活跃问题

```bash
cat state/ISSUE_INDEX.md
```

### 创建新BUG

1. 创建 `docs/00-memos/BUG-YYYYMMDD-XXX_描述.md`
2. 填写模板
3. 更新 `state/ISSUE_INDEX.md`
4. 创建TODO指派

### 关闭问题

1. 运行验证
2. 记录验证结果
3. 更新 ISSUE_INDEX 状态

### 查看历史BUG

```bash
ls docs/00-memos/BUG-*
```

## 八、与现有规范的集成

### 8.1 与 state/todos.db 的关系 (v2.3.3+)

| TODO 字段 | BUG 字段 | 说明 |
|-----------|----------|------|
| id | ID | 保持一致 |
| status | 状态 | pending→in_progress→completed |
| priority | 优先级 | high/medium/low |
| description | 问题描述 | 链接到BUG文件 |
| receiver | 负责人 | |

### 8.2 与 memos 的关系

- BUG 存储在 `docs/00-memos/`
- PROPOSAL 存储在 `docs/04-proposals/`
- MEMO 存储在 `docs/00-memos/`

### 8.3 与 skills 的关系

- 问题追踪使用 `oc_collab_issue_tracker` skill
- Skill 内容存储在 `skills/oc_collab_issue_tracker/content.md`
