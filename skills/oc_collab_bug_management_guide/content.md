# OC-Collab Bug管理指南

## 快速参考

### Bug处理流程

```
发现 → 报告 → 分配 → 调查 → 修复 → 合并 → 验收 ✅ → 发布 → 闭环
                                          ↑
                                     验收不通过不能发布！
```

### ⚠️ 关键规则

| 规则 | 说明 |
|------|------|
| **验收必须在发布前** | 验收不通过不能发布，避免撤回 |
| **P0立即修复+验收** | 缩短修复-验收-发布周期 |
| **验收后才能发布** | 只有验收通过才能打Tag |

| 等级 | 定义 | 响应时间 | 示例 |
|------|------|----------|------|
| **P0** | 阻塞协作流程 | 立即修复 | TODO不同步、签署失效 |
| **P1** | 影响功能使用 | 本次会话 | 命令参数错误 |
| **P2** | 轻微问题 | 下个版本 | 文案错误 |
| **P3** | 建议改进 | 可推迟 | 体验优化 |

| 场景 | 行为 |

## Bug分配环节

### TODO分配规则

```yaml
todos:
  - id: "TODO-BUG-XXX"
    content: "修复 BUG-YYYYMMDD-XXX: 简明标题"
    from: "agent1"        # 发现者
    to: "agent2"          # 修复者
    phase: "bugfix"
    priority: "P0/P1/P2"
    bug_id: "BUG-YYYYMMDD-XXX"
    status: "pending"     # pending/in_progress/completed
    created_at: "timestamp"
```

### 分配检查清单

```bash
# 分配Bug后必须：
1. ✅ 创建TODO任务（只创建"修复Bug"的TODO）
2. ✅ 指定 from（发现人）
3. ✅ 指定 to（修复者）
4. ✅ 指定 priority（严重程度）
5. ✅ 关联 Bug ID
```

### ⚠️ TODO创建规则

| 规则 | 说明 |
|------|------|
| 只创建"修复Bug"的TODO | ✅ 分配给相关Agent |
| 不要提前创建"验证修复"的TODO | ❌ 等修复者提交后，由验收者自主创建 |
| 不要代他人创建TODO | ❌ 谁需要谁创建 |

### 分配规则

| Bug严重程度 | 谁修复 | 响应时间 |
|-------------|--------|----------|
| P0 | 任何人 | 立即 |
| P1 | 相关Agent | 本次会话 |
| P2/P3 | 相关Agent | 下个版本 |

## Bug修复环节

### 修复步骤

```bash
# 步骤1: 创建修复分支
git checkout -b fix/BUG-YYYYMMDD-XXX

# 步骤2: 修复代码
# 编辑相关文件

# 步骤3: 编写测试
# 确保修复后测试通过

# 步骤4: 提交修复
git add .
git commit -m "fix: 修复 BUG-YYYYMMDD-XXX (简明描述)"

# 步骤5: 创建Pull Request
```

### 修复提交规范

```bash
# 修复提交消息
fix(BUG-YYYYMMDD-XXX): 简明描述

[body]
- 问题描述
- 修复方案
- 测试结果

[footer]
Closes #BUG-YYYYMMDD-XXX
```

### 修复后必须更新TODO

```bash
# v2.3.3+ 使用SQLite，无需git add YAML文件
# 1. 标记TODO完成
oc-collab todo complete TODO-X-XXX
# 2. 或者更新状态
oc-collab todo edit TODO-X-XXX --status completed
```

### 修复检查清单

```bash
# 修复完成后必须：
1. ✅ 测试通过
2. ✅ 代码审查通过
3. ✅ 提交信息规范
4. ✅ 更新Bug报告状态
5. ✅ 更新TODO，告知Agent1已修复
```

### ⚠️ TODO更新规范 ⭐

| 规则 | 说明 | 示例 |
|------|------|------|
| 在TODO标题标注"已修复" | 让Agent1明确知道状态变化 | `修复 BUG-XXX（已修复）` |
| 保持简洁 | 不需要添加冗长的验证步骤 | Agent1自然会去验证 |
| 任务交接给Agent1 | TODO状态改为pending，等待验收 | `status: pending` |

## Bug闭环环节

### 验收确认 ⭐

**验收是独立的环节，必须正式签署，不能只说"测试通过了"**

### 验收与发布的顺序

```
修复 → 合并 → 验收 ✅ → 发布
                  ↑
            验收不通过不能发布！
```

### 签署模板

```markdown
## 验收确认

### 测试验收

| 测试项 | 结果 |
|--------|------|
| 单元测试 | ✅/❌ XX passed |
| E2E测试 | ✅/❌ XX passed |
| 功能验证 | ✅/❌ |

### Agent 1 签署

| 角色 | 姓名 | 日期 | 确认 |
|------|------|------|------|
| 产品负责人 | Agent 1 | YYYY-MM-DD | ✅ 验收通过 |
```

### ⚠️ 验收检查清单

```bash
# 验收必须完成：
1. ✅ 运行测试并通过
2. ✅ 验证功能修复
3. ✅ 在Bug报告中添加签署表格
4. ✅ 填写正式的签署内容
5. ✅ 提交签署记录
```

## 📚 教训总结（v1.4新增）

### BUG-20260208-003: 测试中发现基础设施Bug

**场景**: v2.2.4功能测试通过后，发现oc-collab工具无法识别v2.2.x项目结构

**新增规则**:

| 规则 | 说明 |
|------|------|
| 测试中发现Bug必须写测试用例 | Agent1负责黑盒测试，必须编写测试代码覆盖Bug |
| 测试代码是Agent1的权限 | 测试是Agent1的职责范围 |
| Bug报告必须关联测试 | Bug报告 + 测试代码一起提交 |
| 回退验收状态 | 发现新Bug后必须回退验收签署 |

### ⚠️ TODO创建规则（v1.4新增）

| 规则 | 说明 | 示例 |
|------|------|------|
| 只创建"修复Bug"的TODO | ✅ 分配给相关Agent | "修复 BUG-20260208-003" |
| 不要提前创建"验证修复"的TODO | ❌ 等修复者提交后自主创建 | 不要创建"Agent1重新测试" |
| 不要代他人创建TODO | ❌ 谁需要谁创建 | Agent1不要替Agent2创建 |

### Bug处理检查清单

```bash
# 发现Bug后：
1. ✅ 编写测试用例覆盖Bug
2. ✅ 验证测试失败（证明Bug存在）
3. ✅ 回退验收签署状态
4. ✅ 创建Bug报告
5. ✅ 创建TODO分配给Agent2（只创建修复的TODO）
6. ✅ 提交变更（测试代码 + Bug报告）
7. ⏳ 等待Agent2修复
8. Agent1看到修复后，自主创建验收TODO
```

### Agent1的Bug处理权限

| 操作 | Agent1 | Agent2 |
|------|---------|--------|
| 编写测试代码 | ✅ | ✅ |
| 创建Bug报告 | ✅ | ✅ |
| 创建TODO分配给Agent2 | ✅ | ❌ |
| 修复代码 | ❌ | ✅ |
| 签署Bug修复验收 | ✅ | ❌ |

## 1. 触发条件 ⭐

**触发关键词**: `test_failure`, `collaboration_slow`, `tool_error`

| 场景 | 触发条件 |
|------|----------|
| 测试失败 | 发现Bug |
| 协作不顺畅 | 发现流程断点 |
| 工具返回异常 | 检查错误信息 |

**参考**: "1. Bug发现环节"

## 2. 操作步骤 ⭐

| 环节 | 步骤 | 操作 |
|------|------|------|
| Bug发现 | 1 | 发现Bug，记录测试输出 |
| Bug发现 | 2 | 分析影响范围和严重程度 |
| Bug报告 | 3 | 创建Bug报告（模板见"Bug报告环节"） |
| Bug分配 | 4 | 创建TODO分配给修复者 |
| Bug调查 | 5 | 调查根因，提出解决方案 |
| Bug修复 | 6 | 修复代码，编写测试 |
| Bug发布 | 7 | 验收通过后发布Patch |
| Bug闭环 | 8 | 签署验收，关闭Bug |

## 3. 输出产物 ⭐

| 产物 | 位置 | 格式 |
|------|------|------|
| Bug报告 | docs/00-memos/BUG-YYYYMMDD-XXX.md | Markdown |
| 测试代码 | tests/test_*.py | Python |
| 签署记录 | Bug报告末尾 | Markdown表格 |

## 4. 验收标准 ⭐

| 标准 | 检查方法 |
|------|----------|
| Bug报告完整 | 按模板填写所有字段 |
| 测试用例覆盖 | 验证测试失败→通过 |
| 修复已合并 | git log 确认合并记录 |
| 验收已签署 | Bug报告中有Agent1签署 |
| 发布已完成 | Git tag 已创建 |
